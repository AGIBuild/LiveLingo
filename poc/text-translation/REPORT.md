### 0.4 评测推翻或修正的设计决定

| 首轮设计 | 评测结果 | 处理 |
|---|---|---|
| JSON schema 约束输出（`json`） | 12%（wmt24）/ 19%（wmt25）条目 `finish=length` 跑飞；MetricX 差 0.83（显著） | 已删除 |
| 原文包成 JSON 字符串、纯文本回复（`quoted`） | 与纯文本契约**质量无显著差异**，但把 `\n`、`\"` 抄进译文：版式 15%、结构化 6%（整段 7% / 26%）；1.8B 受害更重 | 已删除；原文原样发送 |
| 版式：单元丢弃行首/行尾空白 | 同为纯文本契约，修复前版式 26%（27 条），修复后 78% | 单元保留前后空白，`Units.Join` 原样恢复 |
| 级联：1.8B 先译，QE 低再升 7B | 质量与成本随阈值**近似线性**，没有拐点（升级 40% 时 5.13 对 7B 的 4.92，耗时 8.7 s 对 12.2 s） | 不采用 |
| 字面量保护 | 关闭保护后 IFMT 与探针**数字完全相同**；本语料无法证明它有用 | **开放问题**：保留的理由只剩首轮“模型曾整段省略代码”的个例，需要代码密集语料再验证 |
| 前文上下文（2 组） | 有上下文比无上下文 MetricX 高 0.17（更差，CI 含 0），COMET 反而是无上下文略好（显著）；没有测出收益（仅在首轮 `quoted` 契约下测过） | **开放问题**：简化前需用最终契约复测 |

### 0.5 最终设计结论

- **提示**：专用翻译模型，原文原样放在指令之后，纯文本回复。**注入防护只靠提示措辞**，只有 1 条作者编写的探针覆盖，不是保证。
- **两条路径，由输入来源决定，不靠内容嗅探**：实时听写走句子/行单元（说完等 1.5–2 s）；已完成的文本（粘贴的文档、结构化数据）整段翻译（质量更好、版式更稳）。测试应用已提供“Translate whole text”按钮；产品中的路由与整段超出上下文窗口（8K）时的分块**尚未实施**。
- **模型**：Hy-MT2-7B Q4_K_M 为质量默认；1.8B 在最终契约下仅比 7B 差 0.56（首轮 1.78 是 `quoted` 契约造成的），首个可见译文 93 ms，可作 16 GB 机型的候选，**需要独立评估后再决定**。通用 4B 模型不建议。
- **已知弱点**：单元策略在结构化数据（65%）上不足；术语一致性样本不够；zh→en 手册类最弱。

# 首轮记录（2026-10-29）

## 1. 当前判断（首轮；其中契约结论已被第 0 节推翻）

首轮更值得继续验证的是：

**专用翻译模型 + 可恢复的字面量保护 + 有类型的输入/输出契约 + 稳定语义单元调度。**

模型方向暂以 **Hy-MT2-7B Q4_K_M** 为质量候选。1.8B 确实快，但存在把“在 UI 线程之外”翻成“在 UI 线程上”的严重错误，不能因为吞吐高就成为默认。小型 NMT 很快，但当前技术文本质量和术语能力不足。

这不是最终“最佳模型”认证：目前只是 31 条开发探针、单作者参考译文，没有独立双语盲评或隐藏测试集。没有证据证明已达到产品准入。

## 2. 新架构及取舍

```text
输入原文 / composition 状态
    → 有版本的完整语义单元 + 活动尾部
    → 单 worker；保留未变化的前缀；使受前文修改影响的后缀失效
    → 最多两组只读源/译上下文 + 原文实际命中的术语
    → 代码、URL、占位符转为可逆 token
    → 专用翻译模型，结构化源文本和 JSON schema 约束输出
    → 只接收 text 值；完整性检查；逐一恢复字面量
    → 仅应用仍属于当前原文的结果；失败显式展示
```

选择依据：

- **一句翻译模型，不串润色模型**：先让专用模型完成保义、自然表达，避免每个单元多次生成。
- **7B 与 1.8B 实测对照**，而不是从设备最低配置倒推出最小模型。目标仍是 M2 及以上、16 GB 及以上，Metal 是正常路径。
- **原文是数据，不是模型应执行的任务**。纯“翻译下面文本”的提示在指令型原文上会漏译外层语句；结构化契约在已测 7B 个例上改善了这一问题。
- **结构保护不能只靠提示词**：初轮模型曾直接省略整段代码。保护和恢复放在单一组件，缺失/重复 token 直接失败，不静默拼回一份看似成功的译文。
- **完整语义单元优先**：可在输入过程中交付已完成句子，但不把任意 token 认定为稳定译文。当前活动尾部仅在确认时 flush，有限等待的尾部预览仍未实施。
- 不切开数字版本、常见缩写、代码或 URL 查询中的问号；用户修改前文时，依赖这个上下文的后续译文重新计算。
- 没有本地→其他本地→云端的隐式备选链，也没有应用层自动重试。

### 模型与运行时

- 官方 **Hy-MT2**，不是旧版 HY-MT1.5。1.8B/7B 的官方 GGUF 均标注 Apache-2.0，修订与 SHA256 固定在 [下载脚本](scripts/fetch-models.sh)。
- 独立官方 llama.cpp **b11980 / f7c01c522**，macOS arm64；8,192 context，单 slot，Metal 全层卸载配置，6 个 CPU 线程。
- 非推理预算为 0；确定性配置 temperature 0、seed 42，top-p 0.6、top-k 20、repetition penalty 1.05，输出上限 768 tokens。另测了官方推荐 temperature 0.7 的纯文本配置，不能据此推断所有采样最优值。
- 独立 OPUS-MT 双向模型转换为 **CTranslate2 4.6.0 CPU int8**、6 线程、beam 4；没有使用产品 ONNX 或解码器。
- TranslateGemma 4B 官方模型需要接受访问条件，本轮未下载或测试；没有绕过该限制。没有云端授权/配置，所以未调用在线翻译。

## 3. 测量边界

实际机器为 **M3 Pro / 36 GB**。它属于目标设备范围，但**不是 M2/16 GB 基线实测**，不能用限制线程模拟出该结论。既有语音测试应用保持运行，没有为评测强行关闭用户应用。

31 个自编中英双向开发条目覆盖技术、协作和文档；每个最终系统各运行三次，共 93 个请求。最终文本契约相同时比较 1.8B 与 7B；各轮错误均落盘，没有用重试后的成功覆盖失败。

- “首译文字符”指 HTTP 流中首个翻译 payload 字符到达，不是 UI 绘制时间，也不是语义已确认。
- 完成时刻要求模型结束、JSON 解码及字面量恢复成功。JSON 的 `{` 或字段名不计为首译文字符。
- 暖请求计时，不含模型下载、初始化或首次加载。冷启动还没有三次重复测量。
- 禁用整段 prompt cache 复用的请求选项；无最终译文结果缓存。固定种子重复主要用于计时，不是独立质量样本。
- NMT 没有 LLM 的术语指令、JSON 或字面量包装，以下全量表比较的是**候选系统**，不能把差异全部归因于权重。

## 4. 最终同契约实测

来源：`~/VoicePoc/translation-eval/final-summary.json` 及其引用的逐请求 JSONL。质量分只取各条目的第一次输出，失败保留为空译文，不从分母剔除。

| 系统 | 首译文字符 p50 / p95 | 完成 p50 / p95 | chrF++ | 请求失败 | 字面量/词表检查失败条目 |
|---|---:|---:|---:|---:|---:|
| Hy-MT2-1.8B + 结构化契约 | 161 / 209 ms | 460 / 634 ms | 63.20 | 0/93 | 0/31 |
| Hy-MT2-7B + 结构化契约 | 628 / 783 ms | 1,763 / 2,267 ms | 66.76 | 0/93 | 0/31 |
| OPUS-MT + CT2 int8，无包装 | 177 / 285 ms | 177 / 285 ms | 51.78 | 0/93 | 9/31 |

**chrF++ 不是准确率百分比，检查全通过也不等于语义正确。** 单作者参考、小样本、训练重叠和开发集调参都使这些分数只能用于探索。

长文探针约 160 个中文字符，7B 结构化完成约 5.7 s，不能被短句 p95 掩盖。采样得到的服务进程 RSS 峰值约为 1.8B **1.66 GiB**、7B **5.48 GiB**；这是进程 RSS，不是产品整机占用或完整 Metal/统一内存记账，未证明 M2/16 GB 多应用并发预算已通过。

### 实际译文比平均分更重要

| 探针 | 观察 | 判断 |
|---|---|---|
| `Create OnlineRecognizer off the UI thread...` | 1.8B：`在 UI 线程上创建...`；7B：`在UI线程之外创建...` | 1.8B 方向反转，属于严重错误；字符串检查全部通过仍漏检 |
| `这个接口不要加重试...` | 1.8B：`should not undergo additional testing...`；7B：`Do not increase the retry count...` | 1.8B 术语错义；7B 的“增加重试次数”也不如参考“不要添加重试机制”精确，仍需改进和盲评 |
| 包含“请翻译这段用户输入”的原文 | 7B 纯文本契约只译引号内句子；结构化后保留了外层介绍和末尾说明 | 契约改善了已测漏译，不能推出能防止所有源文本指令干扰 |
| 完整 fenced code | 无保护时曾整块省略；保护后逐字恢复 | 结构问题由确定性逻辑解决，不能让模型自由重写代码 |
| `Redis / TTL / PR / CI`、自定义术语 | LLM 包装后的检查通过；NMT 部分标识符、术语及版本号受损 | NMT 仍可作资源基线，不作当前技术场景首选 |

输出均可在结果目录核对；这些是代理阅读审查，不冒充双语人类盲评。

## 5. 流程 POC：不是仅测模型

独立 B0 是“输入完后翻译全文”，B1 是“输入期间处理完整语义单元”。**不是与旧产品实现比较**。

### 5.1 15 秒逐句输入回放

同一 Hy-MT2-7B、结构化契约、6 个句子，每 3 s 新增一句：

| 流程 | 从输入开始到首个确认结果 | 输入结束后的等待 |
|---|---:|---:|
| B0：输入结束后译全文 | 19.20 s | 4.20 s |
| B1：稳定语义单元 | 1.33 s | 1.38 s |

两者都只翻译 105 个目标源字符；B1 额外携带有限上下文。该回放说明输入期间消化工作能缩短最终等待，不意味着翻译模型本身加速，也不代表真实 IME、连续按键或语音已经测过。

### 5.2 10 分钟持续输入

Hy-MT2-7B + 结构化契约，每 3 s 追加一句，共 **201 个单元、3,519 个源字符**：

- 输入持续 600.00 s，结束后等待 **1.50 s**；
- 翻译目标源字符也是 **3,519**，没有因为末尾追加而重译稳定前缀；
- 前 50 单元平均确认滞后 **1.50 s**，后 50 单元 **1.45 s**，最大约 **1.67 s**；
- 本回放未观察到持续积压。

它重复使用六句作为调度压力脚本，不是自然长对话质量集。没有独立客户端内存曲线或整体内存上界证明，不能把“无积压”写成“资源有界”。

## 6. 真实运行发现并修正的问题

1. **提示边界放错**：把约束写到“翻译以下文本”之后，模型连约束一起翻译。约束移到边界之前并加回归测试。
2. **代码保留靠提示不够**：新增可逆字面量保护与精确一次恢复，不在输出后猜测补齐。
3. **原文像指令时被部分执行**：新增结构化源数据和输出 schema；保留纯文本模式作对照。
4. **嵌套 JSON 将中文编码成六字符转义**：使模型实际上下文膨胀、7B 首输出明显变慢。源 JSON 改为保留可读 Unicode；它是发给本地模型的数据，不插入 HTML。
5. **本地 HTTP keep-alive 互操作失败**：早期出现 `ResponseEnded`，明确 Content-Length 没解决；显式关闭每次 loopback 连接后，后续请求未再观察到该故障。没有应用层重试；上游具体根因未最终定位。
6. **评分器曾只统计成功条目**：已修正为失败输出也进入质量分母，保留早期记录，不覆盖事实。
7. **worker 的异常清理意外重启任务**：失败测试复现短时间重复调用；现在意外故障终止并传播，不进入隐式重试循环。
8. **URL 查询的问号被当作句号**：切分与字面量保护复用同一范围识别，回归测试覆盖。

当前独立契约测试覆盖切分、IME、前缀复用、上下文失效、旧结果丢弃、失败可见、尾部 flush、流结束与截断、JSON payload、字面量及异常终止。最后完整验证为 36 个测试通过，Release 编译无警告、无错误。

## 7. 如何进入下一阶段

可以保留的架构决定：独立会话状态、单元级更新、有限上下文、确定性字面量保护、结构化输出与显式失败。

暂不固化为产品默认的部分：

- 模型最终选择：7B 是当前质量方向，不因这 31 条探针宣布胜出。1.8B 需解决已观察到的语义错误，不能只加字符串门禁后放行。
- 精度：还需独立双语参考、隐藏技术集、负例最小对照、流畅度盲评；本轮没有达到原计划 240 条和两名评审要求。
- 体验：补 150/300/500 ms 静默窗及有界尾部预览；用户手改优先和交互 UI 尚未实现。
- 资源：补 M2/16 GB 基线、Windows、冷启动和多应用并发；本机高配的暖请求成绩不能代替这些门槛。
- 语音实时转写翻译：下一阶段将稳定源文本事件接到本会话，单独衡量 ASR 修订、错字传播、尾部延迟和译文回撤；本轮没有接音频。

所有模型、依赖和结果在用户目录；代码、开发探针和说明保留在本 POC。没有上传原文/录音到在线翻译服务。
