> **状态（2026-10-30）：** 文本翻译 POC 已完成多来源语料评测，结果与由此推翻/修正的设计见 [poc/text-translation/REPORT.md](../../../poc/text-translation/REPORT.md) 第 0 节。实时语音翻译尚未开始；产品代码未修改。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Do not modify product translation code before the POC decision gate.

**Goal:** 先证明翻译准确、自然、持续输出，并在 Apple M2 及以上、内存 16 GB 及以上的目标配置中流畅运行，再将胜出流程迁入 LiveLingo，最后接入实时语音。

**Architecture:** 使用专用翻译模型或小型 NMT，配合有版本的语义单元调度；稳定单元保留，活动尾部可修订。文本 POC 与语音 POC 分阶段，复用语音核心而非重造 ASR。

**Tech Stack:** 独立 .NET 10 POC 编排；官方 llama.cpp Metal 运行时与 Hy-MT2 GGUF；公开 OPUS-MT/CTranslate2 为独立 NMT 对照；Foundry 仅作显式授权的可选对照。

日期：2026-10-29。状态：**按用户最新指示完成首轮独立 POC；不读取、引用或迁就产品现有翻译实现，不修改产品翻译代码**。已对比 Hy-MT2-1.8B / 7B、公开 NMT、纯文本/结构化契约及全文/单元流程；结果与未通过项见 [首轮报告](../../../poc/text-translation/REPORT.md)。下方完整准入清单仍包含未实施的后续阶段，不因首轮完成而自动勾选。

默认范围为中英双向、技术讨论/协作聊天/方案文档。其他语言另列，不把中英结论外推。数值均为待验证门槛，不是性能承诺。

**硬件定位：**以 M2/16 GB 实机作为产品性能验证基线，而不是面向最低配置做产品。正常利用 Metal 等可用加速，以准确率、自然度和流畅度共同选择方案，不为模型最小化牺牲质量。CPU-only 是补充对照，不是所有后端的主性能门槛；Windows 以 16 GB 及以上同档设备独立验证。

## 1. 从目标出发的独立设计

不把现有产品的引擎、路由、提示词、防抖或后处理链当作设计依据；不引用产品项目来建立基线。设计的约束只有保义、自然、持续输出、可修订、隐私和 M2/16 GB 资源目标。

对比三个独立方案：

1. **专用翻译 LLM + 语义单元调度**：术语与语境能力较强，采用正确模板、常驻模型和有限上下文，是首选验证方向。
2. **小型 encoder-decoder NMT**：资源与吞吐对照，检查技术文本、混说和语境损失，不预设其质量足够。
3. **远端专用翻译**：可选参考，不作为本地失败后的隐式备选，未授权不调用。

独立基线 **B0** 定义为：相同候选模型、相同最终原文，在输入完成后一次性翻译。**B1** 为输入期间处理完整语义单元，**B2** 增加有限的活动尾部预览。这样只比较模型与新流程的差异，不借旧实现来证明新方案优秀。

## 2. 调研结论与候选

检索日期 2026-10-29；以下能力来自官方资料，**厂家榜单和设备延迟不代替本项目实测**。

### 2.1 第一轮只保留三条路径

| 路径 | 候选与理由 | 必须验证 / 取舍 |
|---|---|---|
| A：轻量专用翻译 LLM，优先验证 | **Tencent Hy-MT2-1.8B，官方 GGUF Q4_K_M**。2026-05-21 发布；官方提供术语、上下文、格式保留指令；权重许可 Apache-2.0 [S1][S2] | 不是之前的 HY-MT1.5。以 M2/16 GB 的 Metal 路径为主测，CPU-only 作对照；验证量化后术语/否定保真、实际首可见译文、是否输出推理。无默认 system prompt，必须使用本模型模板 |
| B：小型专用 NMT，资源基线 | 官方 OPUS-MT 中英双向权重 + **CTranslate2 CPU int8**，不使用产品导出或解码器 [S4] | 先独立进程 POC。没有 Metal 支持证据，不按“Mac GPU 加速”估计性能；上下文与术语约束能力可能较弱 |
| C：用户授权的远端路径 | **Azure Translator NMT**；另作一条 Foundry 低延迟 LLM 翻译质量对照 [S5] | 关闭云端时不调用；未提供凭据也不影响 A/B 验证。记录 API、部署版本、区域、网络、费用；无凭据则报告“未测”，不能填入预测成绩 |

**TranslateGemma 4B**（2026-01-15 发布，55 种语言，Gemma 条款、需接受访问条件）作为质量挑战者 [S3]。4B/7B 模型只要在 M2/16 GB 上满足质量、延迟和资源约束，就有资格成为默认，不因参数量较大而预先排除。较大模型是否入选由实测决定，不靠提高产品硬件基线掩盖问题，也不把 30B 级模型直接设为默认。

Hy-MT2 官方另外提供 2-bit / 1.25-bit 版本。首轮不采用极端量化：磁盘小不等于运行内存小，也不证明技术术语准确。先 Q4 通过再单独比较。

### 2.2 版本与运行约定

调研时核实的官方修订，用于下载前复核并生成 manifest：

- Hy-MT2-1.8B：`9a341cd1b679d3efd23b46e847b01745a71ed792`。
- Hy-MT2-1.8B-GGUF：`a0c709d9fac510f2c807aa3af52872340dc37a4a`，文件 `Hy-MT2-1.8B-Q4_K_M.gguf`。
- TranslateGemma：模型元数据为 `gemma` 许可、`manual` 访问；不得绕过访问审批。

固定模型 SHA256、运行时 commit、量化、提示模板、上下文大小、线程、采样、缓存模式和 stop token。Hy-MT2 官方推荐包含 temperature 0.7 的配置；将其与确定性配置作开发集对照，不擅自把 `temperature=0` 宣称为官方最优配置。

采用非推理模式/正确停止条件；不能用“屏蔽推理显示”冒充“没有花时间推理”。不默认串接润色模型；翻译的自然度首先由译文模型负责。

### 2.3 成熟实践借鉴，但不复制高配栈

- llama.cpp server 已提供量化 CPU/GPU 推理、会话及缓存能力；先测常驻服务和稳定提示前缀，不逐次冷加载 [S6]。
- WhisperStreaming 的 LocalAgreement 展示“临时结果与确认前缀分开”的价值；官方已提示改用 SimulStreaming。后者采用更强的流式策略，但其推荐栈包含 Whisper large-v3 与 EuroLLM-9B、GPU，**不能直接视为已满足本产品 M2/16 GB 基线** [S7]。
- 学习的是质量—延迟—修订成本的联合评估，不是把“ASR 稳定前缀”机械等同于“译文稳定前缀”。中英语序变化使后者不能仅凭原文 append-only 判断。
- Azure Translator 现行官方文档列出 `2026-06-06` GA，支持 NMT/LLM 模式选择，且相对 v3 有破坏性 schema 变化。POC 单独适配，不能沿用旧响应解析器；普通文本 REST 完成响应不等于 token SSE [S5]。

## 3. 推荐流程：稳定单元保留，只处理活动尾部

```text
文本变更 / ASR 原文修订
    → 版本号 + IME composition 状态
    → 结构保护（代码、URL、占位符、产品术语）
    → 已完成语义单元 + 活动尾部
    → 调度器（每会话一个执行中任务；尾部合并为最新版本）
    → 单一选定翻译后端
    → provisional 预览 / final 确认
    → 原文与译文并列，提交仅使用当前版本
```

### 3.1 输入、切分与调度

- 中文输入法 composition 中不发起翻译；composition 结束才进入调度。
- 默认优先在句子或可靠短语完成时翻译，不按单字符调用。活动尾部采用 150/300/500 ms 静默窗、1/2 s 最大等待作 POC 网格，均为候选而非产品参数。
- 稳定前文不因在结尾新增一个词而重译；修改前文时，定位受影响单元，并使依赖它的后续语境失效。
- 稳定单元 FIFO，不能因最新输入到达而丢弃；活动尾部 latest-wins，不能累计过期请求。过期结果即使无法立即取消也不能应用。
- 上下文优先给最近 1–2 个已确认源/译对及命中的小词表；比较零上下文，不发送全部聊天历史。
- 原文版本、上下文版本、语言对、模型/模板版本、词表版本共同决定缓存键；不能跨模式或用户复用结果。

### 3.2 预览与确认不同

一个单元最小状态为 `Pending / InFlight / Provisional / Final / Failed / UserOwned`，以 `(sessionId, unitId, sourceRevision, contextRevision)` 标识结果。

token 流只更新该单元的 provisional 区域。完成、质量检查通过且版本匹配后才确认。**token 不等于可以提交的稳定译文**；如果小型 NMT 以一句为粒度完成就已足够快，不为显示 token 另加复杂服务。

用户改过译文后模型不覆盖；原文随后变化时把该人工译文标为待复核，不偷偷重译。切换语言/模型要形成新版本，杜绝晚到结果串会话。

默认不整体闪空译文，不把新增一句变成全文重绘。UI 以单元更新并限频到约 20–30 Hz；其收益必须与推理时间分开计量。

### 3.3 质量与失败处理

- 保护代码块、API 名、变量、占位符和 URL；注释/说明文字仍需翻译，不能把含英文的整句全部“保护”。
- 只注入原文命中的术语映射；同时测试无关术语误插入。上下文只读，禁止把提示结构、历史句子抄入译文。
- 数字/单位/日期允许合法语言格式转换，比较规范化后的值；否定、条件、程度、主体和时态以专门对照题和人工评审验证。
- 不复用语音整理的 CJK LCS、长度比例或同词删除规则。跨语言重排和句子合并是合法现象。
- 空输出、拒绝、超时、重复循环、格式破坏、后端错误都形成显式失败；保留原文和最近有效译文并标明过期，禁止把原文当成“翻译成功”。
- 后端由用户策略明确选定。没有授权不因质量失败或本地慢而上传；不新增本地→Ollama→云端的静默备选链。

## 4. POC 验证，不以演示代替评测

### 4.1 分开测试模型、调度、真实体验

| 层 | 控制变量 | 对照 |
|---|---|---|
| 文本模型 | 同一完整文本、词表、译向 | Hy-MT2-1.8B / 7B；公开 NMT；获授权的其他挑战者 |
| 交互调度 | 固定模型、相同输入事件 | 独立 B0 全文翻译 vs B1 单元调度 vs B2 尾部预览 |
| 端到端文本 UI | 固定模型与调度 | 粘贴、连打、IME、撤销、改前句、手工改译文 |
| 语音级联 | 固定 ASR 事件与翻译模型 | 等全文、稳定句优先、短语尾部预览 |

模型筛选阶段不启用自动路由、自动重试或多模型润色，以免测到的是另一模型。所有基线和候选固定模型、模板及原文版本。

### 4.2 测试集

1. **通用参考**：从许可允许本用途的 WMT/其他公开中英平行集抽样，人工核对；公开基准存在训练重叠，只作锚点。
2. **产品集**：240 个中英双向条目，覆盖技术讨论、日常协作、方案文档，各 80 条；每类两种译向均衡。来源须为自有/获授权文本，参考译文人工审校，不用同一个候选模型生成答案再给自己打分。
3. **危险变体**：额外至少 60 组否定、例外条件、数字/版本、术语、口语纠正的最小对照；术语与格式正确不能掩盖句意反转。
4. **事件集**：至少 20 条 30–120 s 的真实或手写输入事件脚本，包含 IME composition、前文修订和取消；另有 10 分钟持续输入 soak。
5. **语音后续集**：已获许可的真人音频，包含 1–5 分钟技术口述及目标译文。已有中文转写字幕只能评 ASR，**不能直接当翻译参考**。不用 TTS 替代人声，也不把拼接朗读当自然长口述。

按文档/说话人划分开发集与隐藏测试集。词表、上下文和调度阈值只在开发集调整；冻结后跑隐藏集，不能用同一批挑出赢家又宣称无偏验收。

### 4.3 质量指标

- 主评：盲评 adequacy（保义）/ fluency（自然度），记录 MQM 风格的漏译、增译、错义、术语、格式错误；关键错误逐例审阅。
- 两名双语评审独立标注关键集、分歧复核；无足够评审时明确标注“单人探索”，不伪造一致率。
- 机器指标：SacreBLEU chrF++、BLEU 的完整 signature；COMET 可离线辅助，固定模型/许可，不装进产品运行链路 [S8]。
- 对中英混说/代码标识符分别报告术语精确率和召回率、无关词误插入、占位符/代码恢复正确率、数字值保留率。
- 通过率同时报告“被门禁拒绝但其实正确”的比例，防止靠拒绝全部结果达到零错误。
- 报每类和每译向，不只报平均分；显著性采用按文档分组的配对重采样，不能从一次小样本测试推断显著。

### 4.4 速度与资源指标

每次请求保存同一单调时钟上的时间点：输入事件、composition 结束、入队、开始执行、模型就绪、首可见预览、首确认单元、结束/取消、最后 UI 更新。

由此分离防抖、排队、加载、prefill、decode、网络及渲染；首 token、首可见译文、首确认译文和总完成时间必须分别报告。

- 热请求同一条目至少 5 次；冷启动至少 3 次；随机顺序运行并单列缓存命中与未命中，不把重复缓存计作模型吞吐。
- p50/p95、10 分钟队列趋势、过期应用次数、取消后释放耗时、回撤字符数/修订次数、重译字符量÷新增字符量。
- 记录 RSS/峰值、整机内存压力/换页、CPU 线程、GPU、功耗条件、模型驻留和线程设置。
- 主基线：**Apple M2、16 GB 内存实机**；另测 M2 以上、16 GB 以上配置，M3 Pro/36 GB 作为已有高配参照。macOS 使用正常可用的 Metal 加速；限制线程或只跑 CPU 不能冒充 M2/16 GB 实测。
- Windows：独立验证 16 GB 及以上同档配置，记录具体 CPU/GPU 和可用加速路径；不以 8 GB、低端四核或无独显 CPU-only 设备作为产品验收目标。
- 云端单列 RTT、地区、限流、失联、费用。未获得资源/凭据的格子留空，不估成绩。

### 4.5 初始准入门槛

下列是 POC 目标；未通过则诚实记录失败，不为选中某个模型临时放宽：

| 项目 | 门槛 |
|---|---|
| 严重语义错误 | 隐藏关键集不得出现新增的否定/条件反转、数字值改变、越权执行原文指令；零观察不等于零风险 |
| 一般质量 | 相对 B0 严重/主要错误不增加，自然度不退化；得分与置信区间同时展示 |
| 术语与结构 | 受保护标识符、占位符恢复 100%；词表命中目标 ≥98%，无关词插入 0；按样本量说明不确定性 |
| M2/16 GB 热短句 | 正常加速路径下，20–60 中文字符 / 10–40 英文词，首可见结果 p95 ≤1.5 s，最终结果 p95 ≤4 s；含调度等待、不含首次下载 |
| 相对交互速度 | 同设备同事件集的首确认单元 p95 比 B0 改善 ≥30%，并且质量不退化 |
| 本地资源 | 在 M2/16 GB 上记录文本翻译 UI + 后端的峰值内存、Metal 分配和整机压力；与编辑器及后续 ASR 同时运行时不得持续积压或持续换页。不沿用 8 GB 设备推导的 3 GiB/4 线程硬限制，具体预算按实机结果冻结 |
| 持续性 | 10 分钟无持续积压；最终只处理剩余尾部；所有已过期结果应用次数为 0 |

若没有 M2/16 GB 实机，只能通过“功能/当前设备 POC”，不能进入“M2/16 GB 基线性能已验证”的产品准入；更高配置机器的成绩不能替代基线实测。

## 5. 第二阶段：实时转写翻译

文本 POC 胜出后，优先采用 **ASR → 有版本的稳定原文单元 → 翻译**，并列展示原文和译文。复用 [语音识别设计](../specs/2026-10-29-voice-dictation-design.md)的时间轴、原文恢复、用户优先和尾部提交。

不默认等待整理模型：比较二遍原文直接翻译与整理稿翻译，确定是否值得增加延迟及改写风险；两个文本来源不能同时悄悄争写同一译文。

分三种策略对照：

- S0：录完后翻译，作质量/等待基线。
- S1：稳定句/可靠短语翻译，先保证连续性和可追溯，作为推荐起点。
- S2：活动尾部有限前瞻的 provisional 翻译，必要时修订尾部；原文稳定不意味着译文前缀一定稳定，只有完整语义单元通过判定才确认。

句末否定、中文长修饰语、英文从句和口语自纠是专门挑战题。比较译文质量、首确认延迟、句尾到稳定译文延迟、字幕回撤、ASR 修订引发的重译成本及共享 CPU/GPU 竞争。

先用人工转写驱动相同事件测 MT 上限，再用实际 ASR 结果测级联损失；不能把所有错译归给 MT，也不能把 ASR CER 当翻译质量。实时模拟必须 1×，加速回放只用于离线正确性。

SimulEval 的 AL/LAAL 等时延思想可参考，但中英 tokenization 和长度偏差要声明；产品主要报告用户可观察的原句结束→译文确认时间与修订量，不只报一个平均延迟 [S9]。

Azure Speech 可同时给出 interim/final 转写与译文，作为**独立云端授权**的可选端到端对照；这会上传音频，不等同于只授权文本翻译 [S10]。大 GPU 直接语音翻译方案不列默认。

## 6. 分阶段执行清单

本节是完整 POC 与产品准入清单；首轮的实际覆盖见报告。基线为独立 B0，不含相对旧产品提速的实测结论。

### P0：固定当前基线，先测证据

- [ ] 在独立 `poc/text-translation/` 建立回放命令和最小测试窗口；不改 `src/LiveLingo.*`。
- [ ] 从零实现独立 B0，不引用任何产品翻译项目；记录模型、参数、输入版本和阶段时间。
- [ ] 创建 schema、去敏/许可清单、开发/隐藏分组；先以最小原文→参考译文样例测试评测器能检出漏译、增译、格式与数值错误。
- [ ] 完成独立模型冷/热与事件回放基线；先测首 token、首可见译文、总完成，不虚报相对旧产品提速。

### P1：筛模型，不叠加调度改动

- [ ] 使用官方模板接入 Hy-MT2 Q4，独立进程跑相同文本；先验证特殊 token、停止、词表、上下文只读。
- [ ] 使用公开 OPUS 权重运行 CTranslate2 CPU int8；记录 tokenizer、转换版本和许可，不使用产品 ONNX 实现。
- [ ] 无云授权时只跑本地；有授权时单列 Translator NMT / Foundry LLM。取得模型访问许可后对比 TranslateGemma 4B，质量有需要时扩展至可满足 M2/16 GB 约束的 7B 模型。
- [ ] 开发集选配置、冻结 manifest、隐藏集评分；按质量、延迟、内存 Pareto 选择，不用一个综合平均分掩盖硬约束。

### P2：验证增量调度与可用界面

- [ ] 新增 POC 的 `TranslationSession` 与修订事件，不复制产品的整个 provider/模型管理体系。
- [ ] 先写能失败的回放测试：在末尾增加一句不重译前文、编辑前句使依赖后文失效、旧结果不得应用、IME 不触发、手改不被覆盖、失败不伪装成功。
- [ ] 用可控延迟/乱序完成的假后端证明状态不变量，再连真实胜出模型；冷加载/推理期间不断输入也要可取消或明确排队。
- [ ] 在相同模型上比较 B0 与增量策略，跑 M2/16 GB 基线性能、更高配置对照及 10 分钟 soak；提供原文/译文、临时/确认状态、有效配置与错误日志。

### P3：语音接入 POC

- [ ] 回放 `~/VoicePoc/recordings/` 或其他获授权真人录音，补人工转写和人工译文，不再下载受限数据冒充商业验收。
- [ ] POC 只适配现有 `DictationSession` 快照/原文事件；比较 S0/S1/S2 和是否等待整理。
- [ ] 双流水线共用设备预算，验证连续 5–30 分钟、否定后置、修订、取消、目标语言切换和提交时剩余尾部。

### P4：设计收敛后迁入产品

- [ ] 交付 `report.md`、逐例结果、时延分布、资源曲线、失败清单和固定模型/运行时清单。
- [ ] 用户通过 POC 窗口盲测，确认质量和体验；未达标保留当前产品默认。
- [ ] 只把胜出模型适配、单一会话调度和必要 UI 状态迁入产品，淘汰被替换路径；不把试验用备选链全部搬进去。
- [ ] Windows/macOS 回归、隐私出口验证、迁移/撤回开关验证后才改默认。

建议产物布局：POC 的编排与评测放 `poc/text-translation/`，模型放用户 cache，测试原文/参考译文及结果默认放 `~/VoicePoc/translation-eval/`。仓库只保留脚本、脱敏且获授权的最小测试样例与报告；秘密、真实工作文本和录音不进 Git。
