# LiveLingo 产品原型 v2

直接用浏览器打开 [index.html](./index.html)，无需启动服务器。这是完整交互设计演示，不是产品实现；不访问麦克风、不运行模型、不连接云端、不写入真实应用。

## 如何体验

1. 右侧选择“和 Agent 讨论”：示例开始听写，点麦克风结束。逐句编辑后可继续录音；Enter 回填示例输入框，不发送。
2. 选择“说中文，写英文”：录音未结束时译文已出现。展开原文对照不会改变英文输出目标。
3. 选择“翻译技术文档”：预设 Markdown 使用整段路径，保留代码与占位符。也可自行输入或粘贴文本。
4. 选择“会议转录”：展开长文工作台，体验暂停、续录、文件选择和导出。
5. 展开“不顺利的情况”：体验整理拒绝、处理未完成、翻译失败、目标失效、没有输入框、无声音、缺权限和模型准备。

**自由输入的边界**：只有预设语料有模拟整理与译文。任意其他文本会明确显示“原型没有运行模型”，不会伪造翻译成功；可手动编辑译文，或明确选择原文回填。

## 本轮设计取舍

| 主题 | v2 决策 |
|---|---|
| 核心形态 | 短输入使用轻浮窗；同一浮窗可展开为长文工作台，共用一份草稿 |
| 全局呼出 | 继承现有配置；现有默认 Ctrl+Alt+T。原型不注册 OS 热键 |
| 录音 | 点击免按住 / 按住按钮 / 暂停续录均有明确入口；双击热键不是唯一入口 |
| 回填 | 显式选择整理稿、译文或识别原文。原目标失效必须重新绑定，不猜新目标 |
| 发送 | 回填与发送分离，不自动发送，不承诺跨应用的统一撤销行为 |
| 快捷键 | 默认 Enter 回填，可选现有 Ctrl+Enter；Shift+Enter 换行，IME 确认优先，Tab 保留焦点导航 |
| 翻译来源 | 二遍识别原文直接进入翻译；不强制等待整理，不把整理稿冒充翻译来源 |
| 处理路径 | 输入中使用完整句路径；粘贴已完成文本使用整段路径。输入来源决定，用户可显式切换 |
| 人工修订 | 逐句编辑与“这一句用原文”；人工工作稿不被迟到结果覆盖，识别记录只读 |
| 未完成或失败 | 不回填、复制或导出半截结果。明确选原文才使用原文，不静默降级 |
| 隐私 | 默认本地；云端翻译、云端整理、录音留存独立授权。原型没有凭据输入与网络调用 |
| 草稿 | 原型内存保存最近 5 份，刷新清空；正式产品默认不落盘，持久保存另行授权 |

未采纳上轮审查中的“零毫秒呼出”“自动写入后 Esc 撤销”“双击热键消除所有延迟”等未经验证承诺。保真门禁只提示风险，不能证明语义完全正确；原型不提供一键采纳已被判定改错单位的候选。

## 能力覆盖

- 听写、实时尾部、二遍原文、整理、逐句编辑、追加、暂停续录。
- 中文 ↔ 英文实时翻译、文本输入、完成文本整段翻译。
- 文件选择、转录时间轴、TXT / Markdown / SRT 导出。SRT 时间是示例，不是真实音频对齐。
- 托盘、最近草稿、失效目标重新绑定、无目标复制。
- 六个设置页：通用快捷键、语音转录、整理翻译术语、隐私云端、性能模型、关于诊断。
- macOS / Windows 键位展示、浅色 / 深色、减少动画、窄视口、键盘焦点与中文输入法保护。

**产品验证尚未完成**：语音与翻译联合资源调度、M2/16 GB 目标机表现、Windows 实机、全局按键手势、跨应用光标捕获与回填、长录音资源上限、真实文件任务及音频对齐。系统声音、说话人分离、TTS 没有已验证设计，不制造可用入口。

## 验证

原型行为测试不依赖第三方包：

```bash
node --test prototype.test.cjs
```

浏览器检查使用 Playwright（需在测试环境中安装 Playwright 与 Chromium，不向产品添加依赖）：

```bash
node browser.test.cjs
```

如果 Playwright 在独立目录安装，可设置 `NODE_PATH` 为该目录的 `node_modules` 后执行。浏览器检查会重新生成以上设计截图。

已验证 **18 个草稿行为测试 + 20 个 Chromium 浏览器场景**，包括录音中可见译文、人工编辑不覆盖、单句回原文、输入法、回填键、目标失效、无目标复制、处理未完成、草稿恢复、转录续录、托盘、六个设置页、独立云端授权和窄视口布局。浏览器测试确认零脚本异常、零 HTTP/HTTPS 请求；窄视口浮窗不遮住原输入框且不裁切顶部。

复核发现并修复的边界问题有回归测试：修改原文不得恢复失效目标；恢复草稿同时恢复翻译方向；开始录音不得丢弃尚未触发的文本任务。任务恢复、快捷键回填和原输入框遮挡问题也已实际验证。

这些结果证明原型可操作，不证明真实识别质量、模型速度或“世界最佳体验”。下一步用真人任务评估首次完成率、误回填率、修订成本和长口述恢复，再决定产品实现。
