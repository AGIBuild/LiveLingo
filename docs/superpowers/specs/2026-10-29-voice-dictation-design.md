# 中文语音输入：已验证架构与产品迁移设计

日期：2026-10-29。状态：**POC 核心已验证，产品迁移尚未实施**。

本文固化的是处理流程、不变量和验证方法，不是“某个模型永远最好”的结论。依据为 [POC 说明](../../../poc/voice-dictation/README.md)、当前工作区实现与本机评测产物；用户已在测试应用中手工确认效果良好。没有证据表明其已达到微信或豆包的准确率。

## 1. 范围与结论

- 产品支持 Windows、macOS；本轮实际验证平台只有 macOS arm64、M3 Pro、36 GB。
- 产品性能验证基线为 **Apple M2 及以上、内存 16 GB 及以上**，以 M2/16 GB 实机验证目标范围的起点；不以最低配置设备定义产品目标。Windows 使用 16 GB 及以上的同档配置独立验证，不将其性能直接等同于 M2。
- 使用 .NET 10、Avalonia，保留“任意位置唤出草稿、确认后写回原输入位置”的产品交互。
- 核心采用 **持续流式识别 + 片段二遍识别 + 按段整理 + 保真判定 + 显式提交**（“段”见 [整理与窗口缩放设计](./2026-11-02-passage-cleanup-and-resize-design.md)）。
- 用户始终能查看实时识别、二遍原文和整理结果；整理结果不能覆盖原文记录。
- 默认本地处理。云端必须显式授权；模型下载、联网翻译和上传录音是不同的权限。
- POC 测试窗口已支持麦克风和录音留存；全局快捷键、目标输入框写入及 Windows 行为不在本轮验证范围。

## 2. 必须保留的架构

```text
麦克风：16 kHz、单声道、40 ms 一帧
    │
    ├── 用户授权的录音存储：WAV + 参考文本 + 处理记录
    │
    └── 音频时间轴
          ├── 持续流式 ASR ─────────── 实时文本
          └── VAD：提出切分候选，不拥有“哪些声音值得识别”的决定权
                    │
             会话层决定硬/软切分
                    │
             相同音频范围的二遍 ASR
                    │
             按片段顺序归并原文
                    │
             完整句 + 未完成尾部
                    │
             攒成段（长停顿 / 够长 / 停止时成段）
                    │
             按段整理，前文只读
                    │
             保真判定 ── 不通过：保留原文并标明原因
                    │
             可审阅草稿 ── 用户确认 ── 提交快照
```

职责只实现一次：

| 职责 | POC 中唯一归属 | 产品中的边界 |
|---|---|---|
| 录音与格式转换 | [MicrophoneRecorder](../../../poc/voice-dictation/src/Dictation.Audio/MicrophoneRecorder.cs) | 平台适配层，不包含断句或模型选择 |
| 会话时间轴、断句调度、顺序归并、提交 | [DictationSession](../../../poc/voice-dictation/src/Dictation.Core/DictationSession.cs) | 平台无关核心；UI 和回放工具共用 |
| VAD、实时与二遍模型 | [Sherpa 适配器](../../../poc/voice-dictation/src/Dictation.Asr.Sherpa) | 实现现有识别接口，不创建第二套会话 |
| 目标句整理 | [LlamaCleaner](../../../poc/voice-dictation/src/Dictation.Cleanup.Llama/LlamaCleaner.cs) | 只生成候选文本，不直接更新 UI |
| 候选文本是否可以应用 | [FidelityGate](../../../poc/voice-dictation/src/Dictation.Core/FidelityGate.cs) | 保真规则集中维护，不散落到提示词和 UI |
| 模型键与默认参数 | [ModelCatalog](../../../poc/voice-dictation/src/Dictation.Models/ModelCatalog.cs) | 迁移时并入产品现有模型目录，不长期保留平行目录 |
| 草稿展示、用户修改、输出确认 | [测试窗口](../../../poc/voice-dictation/src/Dictation.TestApp) | UI 只消费状态和发命令 |

### 2.1 连续识别，而不是“逐段重新开始听”

短暂停顿不能重置实时流。每个呼吸都重新创建流会丢失上下文，损坏后续识别。当前硬停顿或软切分才关闭并重建实时流。

本轮 X-ASR 的回放记录没有发生可见回撤，这是观测结果，不是所有模型的契约。产品必须允许临时区域修订；不能因为本轮为零就规定所有实时模型都 append-only。

### 2.2 VAD 管切分，不管内容

远场真人音频曾出现：实时 ASR 识别了整句，VAD 只检出其中很短的一段。若二遍只读取 VAD 段，正确实时文本会被残缺原文覆盖。

因此区分：

1. **流消费边界**：实际送入实时识别器的样本范围。
2. **解码边界**：二遍读取的音频范围，可以基于首个出字证据和末尾证据去除静音。
3. **VAD 语音边界**：用于切分和测量，不等于解码边界。

POC 用首个实时文本前的余量、VAD 和最后出字位置共同确定解码范围。迁移时必须独立保存上述边界：尾部裁剪不能使下一片段的消费边界倒退；padding 不能跨越已经消费的上段而重复解码。要用带样本索引的单词边界测试证明无丢字、无重字，不能只比较总音频长度。

### 2.3 两类切分，不能等价处理

- **硬切分**：VAD 不在语音中，且距最近检测段结束达到硬停顿；当前尾部可作为句子结束。
- **软切分**：一句过长，在下一处候选停顿关闭声学片段，但不宣称语义结束；文本尾部继续衔接。
- `12 s` 是软切分的触发条件，**不是严格最大片段时长**。没有可用停顿时仍可能更长。
- 流式 X-ASR 不保证在片段结束时补句号。边界来自二遍结果、句子分割器和会话的硬切分语义，而不是等待流式标点。

### 2.4 二遍原文与整理分离

二遍结果按片段顺序归并，不能按返回先后拼接。原文完成断句后，整理可在用户继续说话时运行，不等整段口述结束。

单个整理任务只获得：

- 当前目标句；
- 最多两句只读前文；
- 后文是否仍在继续的 `Continues` 标记；
- 本次会话术语表。

不传入后文正文，避免把后文抄入当前句。前文仍可能泄漏，所以提示词之外还要执行保真检查。不得为了减少上下文泄漏而丢掉所有必要语境；上下文数量需要对照评测。

## 3. 草稿状态与所有权

保留三条证据链：

- `LiveText`：实时模型最终输出，供诊断。
- `RawText`：二遍归并的原文，不包含整理改写。
- `Text`：经过保真判定或用户修改后的工作稿。

句子状态由核心维护：`Pending → InFlight → Cleaned / Rejected`；无整理或超时保留为 `Raw`；用户修改后为 `UserOwned`。

核心不变量：

1. 音频采集不等待模型推理。
2. 已归并的片段顺序不变；临时识别尾部和已归并原文分区展示。
3. 整理任务不能修改目标句以外的文本。
4. 用户修改优先，晚到的模型结果不得覆盖用户文本。
5. 被拒候选及拒绝原因可审计，不能伪装成成功整理。
6. 同一会话 `CommitAsync` 返回同一任务结果。**这不等于 OS 文本注入已实现 exactly-once**。

## 4. 当前默认配置与取舍

这些是工作区的已测起点，不是硬编码的永恒阈值。

| 项 | 当前值 | 取舍 |
|---|---|---|
| 实时 ASR | X-ASR zh/en，480 ms，int8 | 首字反馈优先；160/960 ms 尚未完整对照 |
| 二遍 ASR | Qwen3-ASR-0.6B，int8 | 真人口音样本上综合较好；不是每种任务最优 |
| 整理 | Qwen3.5-4B，Q4_K_M | 本机可按段运行（一段约 200 字，约 4 s），停止后整篇润色（约 250 字 4–6 s）；M2/16 GB 基线尚需实测 |
| VAD | Silero，阈值 0.35，最短静音 250 ms | 三档阈值对照后的折中；并非所有数据集上单调改善 |
| 硬停顿 | 800 ms | 避免每次换气都断流 |
| 软切分触发 | 12,000 ms | 控制片段增长，但还需迁移时补无停顿策略 |
| 文本尾部强制成句 | 90 字符 | 防止无标点内容无限积累，不保证语义完整 |
| 成段停顿 | 3,000 ms | 说话人停下这么久，攒着的句子成为一段，立即整理 |
| 成段长度 | 200 字 | 达到即在句末成段，长篇口述不必等到停顿 |
| 前文 | 约 300 字（整段，由近及远，至少上一段） | 小上下文降低成本；不得输出前文 |
| 首次出字回看余量 / 尾部证据余量 | 3,000 / 300 ms | 经验启发式，不是模型对齐精度保证 |
| 二遍音频 padding | 200 ms | 不得造成跨片段重复 |
| 二遍异常长度 | `字母数字数 > 音频秒数 × 15 + 10` | 拦已观察到的重复循环；不是普适语速上限 |
| 提交总等待预算 | 15,000 ms | 超时要明确标记，不再无期限等待 |

默认依赖为 sherpa-onnx 2.0.1、LLamaSharp 0.30.0；模型文件清单见 [下载脚本](../../../poc/voice-dictation/scripts/fetch-models.sh)。迁移应固定模型修订、文件哈希和运行时版本，不能只固定文件名。

备选项：

- X-ASR offline：速度较低开销，在会议、网络视频和中英样本上有竞争力；但口音集弱于 Qwen3。
- Fun-ASR-Nano：部分口音优秀，但曾陷入重复解码，标点偏少；保留为对照，不根据单个合成集晋升默认。
- SenseVoice：可作小型基线，目前样本上未体现更好的综合质量。
- 整段录完后统一识别、整理：实现简单，但不能持续提供整理结果，长口述等待随文本增长；不作主架构。

## 5. 保真策略的边界

当前门禁检查数字丢失/新增、英文术语变化、长度比例、CJK 字符对齐、无法解释的删除、多行提示词回显，以及引号/括号净平衡变化。允许解释为语气词、重复、自我纠正或词表替换的删除。

**不能据此宣称“不新增事实、不丢信息”已被证明：**

- 单字替换、否定词删除、主体或条件变化仍可能漏过。
- 数字子串检查不等于数值、单位、日期和数量级相等。
- 净平衡不等于引号/括号严格嵌套正确。
- 长度阈值可能误拒正确的去口头语处理。
- 它针对同语言整理，**不能直接用于跨语言翻译**。

因此原文回看、拒绝原因和人工确认是架构要求，不是临时调试功能。默认保守，不用 LLM 的“自评正确”替代判定。

## 6. 证据及其适用范围

### 6.1 真人音频：识别精度

依据本机 `poc/voice-dictation/results/final-<数据集>-<模型>.json`。每个数据集内为逐片段 CER 的算术平均，忽略标点、空白和大小写；不是整套语料的 pooled CER。各列样本、说话人分布不同，不能直接比较难度或宣称统计显著。

| 二遍模型 | KeSpeech 23 条 | 会议 20 条 | 网络视频 10 条 | ASCEND 中英 8 条 |
|---|---:|---:|---:|---:|
| Qwen3-ASR-0.6B | 8.1% | 9.9% | 10.1% | 17.7% |
| X-ASR offline | 15.3% | 9.8% | 9.5% | 13.5% |
| Fun-ASR-Nano | 9.3% | 10.3% | 15.3% | 15.2% |
| SenseVoice | 13.6% | 11.2% | 13.2% | 14.6% |
| 仅实时流 | 24.2% | 12.8% | 12.6% | 15.8% |

识别器筛选主要使用 `--pace 4 --cleaner none`，它测识别文本，不证明实时运行延迟。小样本只支持当前默认选择，不支持“Qwen3 在中英混说最好”的结论；该列中它甚至弱于仅实时流。新增词表密集真人语料后必须重评。

### 6.2 实时性与整理

- 旧版 X-ASR 二遍配置的 322 s 合成 soak：56 句、音频积压最高 40 ms、提交等待约 1.4 s。**不能把这个延迟归给最新 Qwen3 默认配置，也不能由此推出长录音内存有界。**
- 最新 Qwen3 二遍 + 整理的真人回放：网络视频 10 条，平均提交等待约 2.9 s、最高 5.9 s；ASCEND 8 条，约 2.0 s、最高 2.9 s。
- 两套真人整理共 208 句，59 句有改写、14 句被门禁拒绝。门禁拦截了翻译原文、上下文泄漏和凭空补词等问题；之后还补了引号平衡检查，因此这些数量不是所有最终规则的最新接受率。
- 整理删除口头语会让“对口述逐字稿的 CER”变差，故整理质量以保义盲评为主，不能追求最终 CER 越低越好。
- 截至本次固化，最近完整验证为 58 个核心测试、1 个真实模型 UI 测试通过。存在一次未复现的会话测试失败记录，不能写成“从未失败”。

### 6.3 数据授权与复现

录音在用户目录 `~/VoicePoc/recordings/`，真人参考集在 `~/VoicePoc/reference-corpus/`，不提交到 Git；合成音频只作工程回归。复现命令和数据构建见 [POC 说明](../../../poc/voice-dictation/README.md)。

必须纠正旧记录中的授权简写：

- [KeSpeech 官方许可](https://github.com/tzyll/KeSpeech/blob/main/dataset_license.md)明确限制非商业用途、改编及分发。历史结果只作探索记录，不能作为商业产品准入依据；继续用于本产品前须取得许可或更换数据。
- [WenetSpeech 官方仓库](https://github.com/wenet-e2e/WenetSpeech)要求阅读许可并申请下载；镜像可访问不代表已获得全部使用权，迁移评测前核对授权。官方也记录了 TEST_NET 标签错误。
- [ASCEND 数据卡](https://huggingface.co/datasets/CAiRE/ASCEND)标注 CC-BY-SA-4.0；使用和衍生分发须遵守署名及相同方式共享等条款。
- 可复现清单还须保存原始 utterance ID、说话人/会话 ID、来源修订和音频哈希。当前导入脚本生成的拼接片段不是自然连续口述，不能用其推导长程语境能力。

## 7. 迁移顺序与验收门

### M1：移植核心，不改产品交互

把已验证的会话、接口和状态模型接入现有 Core；替换旧语音处理路径，而不是同时维护两套断句、整理或模型服务。测试窗口和回放工具仍引用同一个核心。

先补齐 POC 尚未完成的可靠性：

- 无界音频/推理队列改为可度量的容量与处理预算；不得静默丢采集帧，不能跟上时停止并明确保留录音。
- 音频缓存采用保留必要上下文的窗口，录音写盘离开实时音频回调；测内存而不只测积压。
- 提交超时后冻结结果；取消并等待所有 worker/native 调用安全退出，杜绝迟到二遍结果改写提交快照、释放后继续推理。
- 把识别/整理失败变成结构化错误和可见状态；现有异常后保留实时原文是明确降级，不得无声掩盖。
- 术语表、模型版本及有效参数进入每次录音记录；权限撤销、磁盘满、崩溃残留录音有明确处理。

### M2：接入平台交互

平台层实现全局快捷键、按住/锁定录音、目标输入位置捕获与重新校验。用户确认才写入；目标失效保留草稿，禁止发送到新前台窗口。文本注入幂等需单独验证。

### M3：跨平台与目标配置验证后发布

至少覆盖 macOS M2/16 GB 基线和更高配置，以及 Windows 16 GB 及以上的同档设备。macOS 正常使用 Metal 等可用硬件加速；CPU-only 仅作补充诊断，不作为全产品性能目标。测试真人近讲/远讲、中英技术术语、否定/数字、自我纠正、5–30 分钟口述、取消/超时和用户编辑竞态。

迁移准入不是“所有测试绿”一项：同一授权语料对照不退化、首字与整理滞后可接受、积压不持续增长、内存有界、原文可恢复、隐私出口可审计。没有 M2/16 GB 实测前，不把 M3 Pro/36 GB 的体验外推到产品验证基线。

## 8. 后续翻译接口

后续实时转写翻译消费**有版本的二遍原文单元**，不强制等待整理完成。原文、整理稿、译文分别保留；默认翻译忠实原文，不能把“清理 → 翻译 → 再润色”串成每句话必经的三次生成。

先完成 [文本翻译及实时转写翻译 POC 计划](../plans/2026-10-29-translation-poc.md)，证明文本翻译的质量、调度和 M2/16 GB 目标配置下的性能，再接语音事件。语音识别的保真原则保留，但跨语言语义重排与增量提交需要独立验证。
