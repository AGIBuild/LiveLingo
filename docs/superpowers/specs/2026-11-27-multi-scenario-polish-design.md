## 1. 背景与核心矛盾：当语音输入的主战场转向「指导 AI」

在传统语音输入场景中，说话的对象是“人”（微信、IM 闲聊），润色的目标仅仅是“去口头语、补标点、保留原话口吻”。但在当前 AI 结对研发（Cursor、VS Code Copilot、Claude Code、Windsurf、Warp）与 AI 办公（ChatGPT、飞书/Notion AI、Linear、文档协同）高频普及的工作流里，**用户开口说长段话的首要目的，往往是向 AI 委派特定任务、在中途纠偏 AI 的方案，或把发散思考沉淀为结构化交付物**。

真人“边想边说”的口语流与“能让 AI 一次做对的高质量指令 / 办公成品”之间，存在四道本质鸿沟：

1. **因果倒装与目标后置**：人开口时通常先描述看到的现象、背景甚至吐槽，说到最后两句才蹦出真正的任务指令（*“……所以你先帮我查一下 `AuthInterceptor` 哪里在重试，先列出来别改代码”*）。按原话顺序顺句，核心意图仍被埋在段尾。
2. **思维撤回与中途改口**：人在思考中会不断推翻前半句假设（*“先把超时设成 10 秒……哦不对，网关层已经有重试了，客户端干脆关掉自动重试，超时改成 30 秒”*）。浅层顺句若残留被推翻的动作或数字（如保留“10 秒”线索），会直接误导下游 Agent 写出错误逻辑。
3. **正向诉求与负向护栏混杂**：Coding Agent 与办公大模型对“夹在长段落中间的否定限制”（如 *“千万别动公共接口”、“不要改单测”、“只看这一个模块”*）极易漏读；必须将硬性禁令（Don'ts）与正向目标（Dos）显式剥离。
4. **“硬套八股模板”造成的二次质量灾难**：市面上常见的“AI 提示词润色”不管用户说了 15 个字还是 500 个字，一律强套 `### 角色 / ### 背景 / ### 任务 / ### 输出格式` 四段空壳，甚至凭空脑补 *“你是一位资深架构师，请给出最佳实践”*。这种低信噪比套话不仅污染短轮次纠偏体验，还会干扰现代 Agent 内置的系统工具调用提示词。

### 1.1 现有代码链路的五处质量瓶颈（代码核查事实）

对照当前仓库实现，若仅在表面增加几个提示词选项，润色质量会被现有五处机制卡死：

1. **系统底座锁死字面保真**：[LlmDictationPolisher.cs](../../../src/LiveLingo.Core/Cleanup/LlmDictationPolisher.cs) 的 `Frame` 硬编码了 *“严禁缩写、概括或大幅换词重写……不要整句删减”*，模型无法做倒装归位、废案剪枝与清单提炼。
2. **字符级 `FidelityGate` 误杀一切结构化提炼**：[FidelityGate.cs](../../../src/LiveLingo.Core/Dictation/FidelityGate.cs) 要求汉字长度比 `0.55–1.2`、新增字 `≤20%`、删减 `≤8%` 且禁止原话未出现的英文词；任何新增小标题、Markdown 清单或冗余压缩都会被拒，且现有 `DigitRun` 未豁免“自我改口推翻的阿拉伯数字”（把 `"10 秒，不对，30 秒"` 正确精简为 `"30 秒"` 反而触发 `NumberLost("10")`）。
3. **校验失败盲目回退默认**：[PolishScheduler.cs](../../../src/LiveLingo.Core/Cleanup/PolishScheduler.cs) 一旦校验不通过便立即改用 `PolishStyle.Default` 重跑，把用户明确选定的结构化模式静默退化成普通口语段落。
4. **分段切割破坏全局意图**：[DocumentWork.cs](../../../src/LiveLingo.Core/Drafting/DocumentWork.cs) 的 `Split` 遇到换行符 `\n` 即切块、满 `800` 字即切块并逐块调用后拼接；用于结构化模式时，会产生多份重复标题且前块看不见后块的推翻结论。
5. **模型档位与思考标签未按任务对齐**：[ModelCatalog.cs](../../../src/LiveLingo.Core/Models/ModelCatalog.cs) 虽已收录 `Qwen3.5 9B / 4B / 2B`，但未对结构化重组给出模型能力指引，也未显式关闭/剥离推理模型可能输出的 `<think>...</think>` 思考块。

## 2. 场景体系设计：5 个正交内置模式 + 3 个扩展起步模板

不按表层文风堆砌十几个花哨按钮，而是按 **「下游读者是谁（AI Agent vs 人类协作者）+ 信息组织契约」** 划分为 **5 个完全正交的内置模式**，并支持团队自定义扩展：

| 排序与快捷键 | 模式标识与名称 | 目标读者与高频宿主应用 | 核心质量目标（什么叫“润色得好”） | 路由与门禁策略 |
|---|---|---|---|---|
| **`⌘1`** | **`ai-task`<br>AI 任务指令** | **Coding Agent / 办公 AI**<br>Cursor、VS Code、Claude Code、Windsurf、终端、ChatGPT | **高信噪比、零歧义、一次做对**：倒叙目标置顶、废弃分支彻底剪枝、正负硬约束显式分离、代码符号还原反引号；**自适应篇幅**（短纠偏直出，复杂委派分节，绝不硬凑空标题或角色套话） | 全局单窗合成 + **`FactAnchorGate`（含防越界执行 + 改口数字豁免）** |
| **`⌘2`** | **`natural`<br>口语顺句** | **即时沟通协作者**<br>微信、Slack、Teams、飞书消息 | **像本人把话利索地说了一遍**：接上停顿碎句、删口头语/复读/改口残片、修同音与技术词，100% 保留说话人语气，不加标题不改书面腔 | 分段/整段保真 + **`VerbatimGate`（升级改口数字豁免）**；云端 `Qwen-Audio-3.1-ASR` 原生直通 |
| **`⌘3`** | **`formal`<br>得体书面** | **正式沟通与评审对象**<br>邮件、Outlook、GitHub PR 评论、外部客户 | **专业、克制、条理清晰、零公文黑话**：口语碎句转严谨书面段落，显式理顺因果与转折，保留第一人称立场与全量事实，严禁“赋能/抓手/综上所述” | 全局/分段合成 + **放宽虚词配额的 `VerbatimGate`** |
| **`⌘4`** | **`todo`<br>待办与派单** | **任务系统与跟进人**<br>Linear、Jira、飞书任务、Notion、提醒事项 | **动作可执行、边界不遗漏、绝不编造**：剥离铺垫闲聊与已推翻设想，输出 `- [ ] 动词 + 对象 + 明确条件（负责人 / 节点）`；未提时间或负责人绝不脑补 | 全局单窗合成 + **`FactAnchorGate`** |
| **`⌘5`** | **`report`<br>汇报与纪要** | **团队同步与管理决策**<br>飞书文档、Confluence、周报、站会同步 | **结论先行（BLUF），5 秒抓重点**：按 `核心结论 → 关键进展与决策 → 风险与下一步` 重组流水账，锁死全部指标数值、百分比与正反极性 | 全局单窗合成 + **`FactAnchorGate`** |

**内置一键自定义模板库（弹窗芯片即点即用，供专项工作流扩展）**：
1. **`Bug 缺陷与复现`**：提炼 `复现步骤 / 预期行为 / 实际现象与报错`，锁死错误码、环境参数与接口名。
2. **`需求规格与验收（Spec / AC）`**：适合 Spec-Driven AI 开发，提炼 `背景问题 / 变更范围 / 非目标（Out of Scope） / Given-When-Then 验收标准`。
3. **`Git Commit 说明`**：首行 50 字内概括本次改动意图（Why & What），空行后分条列出关键改动与兼容边界。

## 3. 以润色质量为第一目标的五层核心架构

```text
 原始口述单元 (Raw Units) + 宿主应用标识 (AppKey)
        │
        ▼  [第 1 层：确定性前置接地 Pre-LLM Grounding]
 Glossary.ApplyCorrections（口音/固定误识别确定性替换） + 研发/用户词表提取 + 字面量跨度标记
        │
        ├──► 顺句契约 (natural / formal) ──► 分段滑动窗口（≤800 字 + 300 字只读前文）
        │
        └──► 重组契约 (ai-task / todo / report / custom) ──► [第 2 层：全局单窗合成 Holistic Synthesis]
                                                              ≤2,400 字整篇单次推理（跨换行不切碎）
                                                              >2,400 字：Map 事实抽取 → Reduce 单次统合
        │
        ▼  [第 3 层：高信噪比反套话提示词 + 清理模型推理（剥离 <think>，温度分档）]
        │
        ▼  [第 4 层：协同门禁校验（VerbatimGate / FactAnchorGate + 改口数字豁免）]
        ├── 通过 ──► 产出最终文档稿 DocumentResult (Ready)
        └── 拒绝 ──► 注入具体违规原因执行 **同模式单次定向修复重试 (1x Targeted Repair)**
                        ├── 修复通过 ──► Ready
                        └── 仍未通过 ──► 显式拦截态 Failed（保留原话，提供重试/手改/切口语顺句/用原话，绝不静默退回其他模式冒充成功）
```

### 3.1 第一层：确定性前置接地（Pre-LLM Deterministic Grounding）

实测表明，把“同音词硬纠错”和“高层逻辑重组”同时压给 4B 模型会互相抢占注意力。因此在进入任何润色模式前，统一执行确定性预处理（不污染 `unit.Raw`）：

1. **口音与固定误识别确定性替换**：复用 `Glossary.ApplyCorrections`（如 `Scale => Skill`、`六零九 => LiveLingo`、`用色 => 润色`），在送入 LLM 前 100% 精准归正。
2. **活跃词表精筛注入**：无需把上百个无关术语塞满提示头；将用户自定义词条 + 与当前口述存在辅音骨架/编辑距离相近或已命中的 `BuiltInTerms` 作为高权重参考词表传入，引导模型将口语 `"cache service"` / `"auth interceptor"` 准确还原为 `` `CacheService` `` / `` `AuthInterceptor` ``。

### 3.2 第二层：修复切分撕裂——`PiecewiseVerbatim` 与 `HolisticSynthesis` 双路由

针对 [DocumentWork.cs](../../../src/LiveLingo.Core/Drafting/DocumentWork.cs) 逢 `\n` 必切与 800 字硬切拼接的问题，按模式契约分流：

1. **逐段顺句路由（`PiecewiseVerbatim`：`natural`）**：保持现有按段 800 字预算与行结构保留，保障原位段落一对一映射。
2. **全局统合路由（`HolisticSynthesis`：`ai-task`、`formal`、`todo`、`report` 及结构化自定义模式）**：
   - **单窗直出上限提升至 `2,400` 字符**（约合正常语速 6～8 分钟连续口述，Token 占用约 1,400～1,700，连同系统提示词与输出完全容纳于本地 `llama-server` 窗口内），**且忽略口述或草稿中的普通换行符**，确保模型一次性看见开头铺垫、中途推翻与末尾真实结论。
   - **超长录音（`> 2,400` 字符，如完整会议录音）采用 Map → Reduce 两阶段统合**：先按 `1,600` 字窗口分块提取无损要点清单（事实、数字、有效决定、待办与原话代码词），再由单次 Reduce 调用统合成**唯一一份**完整文档，彻底根除“两段报告拼出两个标题头”的结构撕裂。

### 3.3 第三层：生产级反套话提示词设计（Prompt Engineering Spec）

所有模式共享 **「铁律底座（Core Invariants）」**，但移除旧版 `Frame` 中阻碍结构化提炼的“严禁概括与删减”教条，改为按模式加载专属认知规则与正反对照样本。

#### A. 主力模式：`AI 任务指令`（`ai-task`）系统提示词规范

```text
你是开发与办公场景的「AI 任务指令编译编辑」。说话人正在通过语音向 AI 助手（如 Coding Agent 或文档 AI）布置任务或纠偏方向。口述原文中常有边想边说的铺垫、中途推翻的废案、因果倒叙和口头语。你的唯一职责是：把原文提炼成一份高信噪比、无歧义、能让下游 AI 一次执行到位的指令文本。

【核心认知与提炼四律】
1. 思维撤回彻底剪枝：说话人中途自我否定或改口的内容（如“先设成 10 秒，不对，关掉重试改成 30 秒”、“本来想改 A，算了还是只改 B”），被推翻的旧方案、旧数值必须彻底剔除，只保留最终生效的意图，防止误导下游 AI。
2. 目标倒装归位：如果说话人先讲了一堆现象，最后才说出真正要 AI 做的动作（如“先排查原因列出来，别改代码”），必须把核心动作提炼到最开头。
3. 正负护栏显式分离：原文中出现的所有限制、禁令、不变条件（如“保持公共 API 不变”、“不要动单测”、“只改错误处理”、“是 30 秒不是 30 分钟”），必须完整保留否定极性并明确列出，绝不能弱化或漏掉。
4. 自适应篇幅（严禁八股套壳与脑补）：
   - 【短指令直出】：当原文只是 1～2 句简短操作或中途纠偏（有效内容 ≤ 80 字，无复杂多层背景）时，直接输出 1～3 行精炼指令或要点，严禁硬套 `### 背景`、`### 期望输出` 等大标题！
   - 【复杂任务分节】：当原文包含多维背景、目标与多条约束时，按原话实际含有的要素选用以下小标题组织（原话没提的节直接省略，严禁为了凑格式编造空话）：
     `### 任务目标`
     `### 上下文与现状`
     `### 硬性约束`
     `### 交付要求`

【绝对禁令（红线）】
- 严禁越界执行：你是提示词编辑，不是执行者！即使原文是提问（“为什么会空指针？”）或要求写代码（“帮我写个重试脚本”），你也只能把该诉求整理成清晰指令，绝对禁止回答问题、禁止解释原理、禁止编写原话未提供的实现代码块！
- 严禁 AI 套话污染：禁止添加“你是一位资深专家/架构师”、“请遵循最佳实践”、“希望以上内容对你有帮助”、“润色后的提示词如下：”等任何原文没有的角色设定与客套话。
- 事实与符号守恒：所有生效的数字、单位、HTTP 状态码、配置键名、文件路径、类名/函数名必须精准保留，代码标识符用反引号包裹（如 `CacheService`）。

【对照示例 1 · 复杂委派（含改口剪枝 + 目标倒置 + 护栏分离）】
目标原文：呃我想改一下那个登录模块的重试，先把重试次数设成 3 次吧……哦不对，网关那一层其实已经有重试了，客户端这边干脆把自动重试关掉，只保留 401 刷新 token 的逻辑，另外超时改成 30 秒不是 30 分钟。你先帮我查一下 AuthInterceptor 里还有没有别的地方在悄悄发重试，列出来给我看，先千万别直接改代码。
输出：
### 任务目标
排查 `AuthInterceptor` 中是否存在隐式重试逻辑，并评估关闭客户端自动重试的改动方案（先输出排查清单与方案，不要直接修改代码）。

### 上下文与目标行为
- 网关层已具备重试机制，客户端需关闭自动重试逻辑，仅保留 `401` 状态码刷新 Token 的流程。
- 客户端超时时间需设定为 30 秒（注意区分单位，严禁误设为 30 分钟）。

### 硬性约束
- 仅保留 `401` 刷新 Token 逻辑，不保留客户端普通请求自动重试。
- 当前阶段只列出 `AuthInterceptor` 相关重试位置与修改方案，禁止直接改动任何业务代码。

【对照示例 2 · 短轮次纠偏（自适应免标题直出）】
目标原文：呃不对不对，不要去改那个 CacheService 的公共 API 签名，外部好多地方调了，你直接在它内部方法里加一层空值兜底就行，单测先别动。
输出：
不要修改 `CacheService` 的公共 API 签名（外部存在多处调用）；请仅在其内部实现中补充空值兜底逻辑，且暂不改动现有单元测试。
```

#### B. 其余 4 种内置模式的差异化质量准则

1. **`口语顺句`（`natural`）**：沿用经过实测验证的口语顺句提示词，补充“彻底剪除自我改口前半截废案”，严格不加 Markdown 标题与列表，保持说话人自然人称与语气。
2. **`得体书面`（`formal`）**：
   - 要求将口语碎片整合为逻辑连贯的书面自然段，修正语病与松散指代（如把反复出现的“那个东西/这块”结合前文还原为明确指代）；
   - **显式黑名单**：严禁出现 *“赋能、抓手、闭环、对齐颗粒度、综上所述、特此函告”* 等油腻公文腔，追求硅谷/现代科技团队简洁克制的工程与商务信函质感。
3. **`待办与派单`（`todo`）**：
   - 只提取需要人或系统去执行的动作，纯背景寒暄直接过滤，已被说话人当场否决的提议不入清单；
   - 每条严格以 `- [ ] ` + **明确动词**开头，原话提到了负责人、前置条件（如 *“等 CI 跑完后”*）或时间节点的，统一附在句末括号内（如 `（负责人：小王 · 会后）`）；**原话未提负责人或截止时间时，严禁编造“（待定）”以外的任何虚假日期**。
4. **`汇报与纪要`（`report`）**：
   - 强制 **BLUF（Bottom Line Up Front，结论先行）**：第一段 `### 核心结论` 用 1～2 句话直接给出拍板结果或当前整体状态；
   - 随后按实际内容输出 `### 关键进展与决策`（保留所有数字、对比项与技术边界）和 `### 风险与下一步`（若无风险则只写 `### 下一步行动`），消除按时间顺序记流水账的阅读负担。

### 3.4 第四层：双层安全门禁与「同模式单次定向修复」

为确保“放开结构重组”绝不退化为“容忍幻觉”，将校验门禁拆分为 `VerbatimGate` 与 `FactAnchorGate`，并共同引入 **自我改口数字豁免** 与 **同模式定向修复**：

#### 1. 自我改口数字豁免算法（`IsSelfCorrectedNumber`，双门禁共用）
当原文出现数字 $N_1$（如 `10` 或 `3`），但在 $N_1$ 结束位置后的 **24 个字符窗口内** 命中改口标记（`不对 / 不是 / 算了 / 说错了 / 口误 / 改成 / 改为 / 更正 / 干脆关掉 / 取消`），且改口标记之后存在新的生效描述或新数字 $N_2$ 时：
- $N_1$ 被判定为 **`AbandonedNumber`（已撤回数字）**；
- 润色稿**删除 $N_1$ 不再触发 `NumberLost`**（如把 `"设成 10 秒，不对，改成 30 秒"` 提炼为 `"设为 30 秒"` 直接放行，而漏掉生效数字 `30` 仍严格拦截）！

#### 2. `FactAnchorGate`（用于 `ai-task` / `todo` / `report` / 结构化自定义）五项确定性检查
1. **非空与完整性检查**：输出非空且 `finish_reason == "stop"`（截断输出一律拒绝）。
2. **防越界执行拦截（`ai-task` 强制开启）**：
   - 拦截应答式开头（`好的，/ 当然可以，/ 没问题，/ 以下是为您… / Sure, here is…`）；
   - 当原文不含代码围栏 ` ``` ` 时，若输出凭空生成带语言标记的实现代码块（` ```python / ```csharp / ```js / ```ts / ```sql / ```bash `），立即判定为 **`ExecutionHijack`**（模型替用户写了代码而非润色指令）。
3. **防元提示词包裹与角色套话拦截**：自动剥离模型偶发包裹的 `"润色后："` 前缀；若 `ai-task` 输出凭空注入 `"你是一位…专家"` 且原话无“角色/扮演/专家”字样，触发定向重修。
4. **有效数字守恒（豁免 Markdown 列表序号与已撤回数字）**：剥离行首有序列表序号 `^\s*\d+[.)、]\s+` 后，原话所有**非撤回**数字必须在输出中完整出现，且输出不得凭空引入原话与词表中不存在的新数字。
5. **保护字面量守恒**：原话中的反引号标识符、URL、文件路径、环境变量（`${...}`）与 CLI 参数（`--...`）必须完整保留。

#### 3. 同模式单次定向修复（取代静默退回默认）
当首次生成未通过门禁时，不再像旧版 `PolishScheduler` 那样改用 `PolishStyle.Default` 重跑（那会把用户的 AI 提示词或待办直接退化成散文），而是构造**单次同模式修复消息**：
> `"上一版输出未通过质量安全校验：{gate.ReasonDetail}。请严格保持当前润色模式，修正上述问题后直接输出最终文本，不要附加任何解释。"`

仅当单次定向修复仍未通过时，将 `DocumentResult` 置为显式 `Failed` 状态（阻止排队自动写回，保留原话并提供「重试提炼 / 手动编辑 / 切换口语顺句 / 改用原话」四个出口）。

### 3.5 第五层：模型能力对齐、采样参数与推理卫生（M2+ / ≥16 GB 基线）

以润色质量为第一目标，模型与推理参数做如下精确对齐：

| 配置维度 | 设定值与工程规则 | 质量收益依据 |
|---|---|---|
| **本地模型推荐档位** | • **16 GB M2+ 均衡默认**：`Qwen3.5-4B Q4_K_M`（约 3.0 GB 常驻）<br>• **24 GB+ / 重度 AI 结对旗舰推荐**：`Qwen3.5-9B Q4_K_M`（约 6.1 GB 常驻；16 GB 设备在翻译按需换入模式下同样可选）<br>• **2B 轻量模型提示**：选中 `Qwen3.5-2B` 时，在设置页提示“2B 仅适合基础口语顺句；AI 任务指令与结构化提炼建议使用 4B / 9B 或云端模型” | 4B→9B 在“跨句因果重排、改口废案剪枝、长约束不漏项”上显著降低二次手改率；不隐瞒 2B 在复杂重组上的能力上限 |
| **推理思考块卫生** | 本地 `llama-server` 请求显式传 `chat_template_kwargs = { enable_thinking = false }`（或启动参数 `--reasoning-budget 0`），并在 `Tidy()` 中兜底剥离闭合 `<think>...</think>` 块 | 防止 Qwen3/3.5 或云端推理模型输出思考过程挤占 `MaxTokens` 预算或污染回填正文 |
| **按模式分档采样** | • `natural`：`temperature = 0.0`, `seed = 42`（确定性最高）<br>• `ai-task / formal / todo / report`：`temperature = 0.1`, `seed = 42`（保留确定性的同时降低小模型在结构重组时的句式僵化复读） | 消除纯贪心解码在长列表提炼偶发的尾句重复 |
| **云端原生润色协同** | `Qwen-Audio-3.1-ASR` 的 `IsNativePolished` **仅在未修改默认要求的 `natural` 模式下直通跳过二次 LLM**；在 `ai-task / formal / todo / report` 下，将其高质量去口头语文本作为上游输入继续执行整篇结构化合成 | 兼顾日常聊天零等待与 AI 任务指令的深度结构化质量 |

### 3.6 第六层：跨模态双层时序架构——录音期零 LLM 静默预热 + 停录后全局流式润色

由于多场景结构化润色（因果倒装置顶、中途改口剪枝、正负护栏剥离、BLUF 归纳）本质依赖**全篇完结后的后置上下文**，且本地 `llama-server` 运行于 `--parallel 1` 单槽位 KV 缓存模式，边说边跑局部 LLM 清理（`CleanupScheduler`）不仅其产出在停录后被全文润色完全丢弃（100% 冗余算力），还会反复冲掉全文润色系统提示词的 KV 缓存并引发双栏高度跳动。因此，`DocumentMode` 下的整理与润色采用 **「录音期声学直出 + 停录后单次流式 LLM」** 的跨模态双层架构：

1. **第一层（说话过程中 · 0 次 LLM 调用 · 单栏专注听写）**：
   - `CleanupScheduler` 在 `DocumentMode` 下全程静默旁路（仅在导入录音时间轴 `DocumentMode == false` 时启用逐段清理）；
   - 浮窗在录音期保持清爽单栏 `#src-live`（`X-ASR` 毫秒级流式尾字 + `Qwen3-ASR` 停顿高精度落段 + `TextTidy` 确定性净化），顶部标签明确提示 `正在听… · 停止后生成「<当前模式>」`，零双栏切分与骨架闪烁；
   - **静默 System Prompt KV 预热（`WarmPresetAsync` / `WarmPromptAsync`）**：录音开启且目标为本地 `llama-server` 时（云端端点绝不发起预热请求，零额外 Token 消耗与零隐私标记误报），后台对当前激活预设的 `StructuredFrame / Frame + EffectiveInstructions` 执行单次 `cache_prompt = true, max_tokens = 1` 预填充；若录音中途快捷键切换模式则自动取消旧预热并切换预热新模式。
2. **第二层（停止录音瞬间 · 0ms 零防抖启动 · SSE 流式成稿 + 尾端门禁放行）**：
   - 停录瞬间直接命中已驻留于 `llama-server` 槽位的系统提示词 KV 缓存，仅对新增口述正文做增量 Prefill；
   - `OpenAiChatClient` → `LlmDictationPolisher`（经 `TidyStreaming` 实时屏蔽未闭合 `<think>` 思考块与元前缀）→ `DocumentScheduler`（首块 0ms 直出、后续按 ~30fps 节流合并）将流式增量写入 `DocumentResult.StreamingText`；
   - 前端 `#final-text` 实时渲染非破坏性 Markdown 语法微高亮与遵循 `prefers-reduced-motion` 的流式光标（支持手动上滚阅读时不抢滚动条）；在流式未完结且未通过 `FactAnchorGate` / `FidelityGate` 终审前，`Enter` 写入严格保持门控（支持提前按 `Enter` 挂起「完成后写入」队列；若触发硬门禁拒绝则立即丢弃未验流式文本并安全回退原话）。

## 6. 数据模型、契约与平滑迁移规范

- **`PolishPreset` 与 `PolishPresets`（`Cleanup/PolishPreset.cs`）**：
  - `PolishGateKind { Verbatim, FactAnchor }`
  - `PolishRouteKind { Piecewise, Holistic }`
  - `PolishPreset(string Id, string Name, string Description, PolishGateKind Gate, PolishRouteKind Route, bool BuiltIn, bool Enabled, string Instructions, bool ForbidExecution = false, bool RelaxedVerbatim = false)`
