# LiveLingo · Qwen-Audio-3.1-ASR 接入与语音识别/润色链路优化设计

日期：2026-11-22。状态：**已实施并通过单元与双引擎浏览器测试验证**。参考：《Qwen-Audio-3.1-ASR 技术系列解读（2）：语音输入，如何跟得上、认得准、写得自然？》及 `arXiv:2610.28711`。相关：[中英混说识别增强与润色门禁设计](./2026-11-13-bilingual-dictation-polish-and-glossary-design.md)、[语音识别设计](./2026-10-29-voice-dictation-design.md)。

## 1. 背景与核心问题分析

此前 LiveLingo 的语音识别阶段硬编码为纯本地双遍架构（`X-ASR 480ms` 流式预览 + `Silero VAD` 切片 + `Qwen3-ASR 0.6B` 离线重解码），并围绕本地 0.6B ONNX 模型的硬限制（`512` 总 KV 窗口、无跨句历史记忆、短音频幻觉、无原生去口头语能力）叠加了多层补偿逻辑。

`Qwen-Audio-3.1-ASR`（特别是面向交互式语音输入的 `qwen-audio-3.1-asr-flash-message` 以及非流式短语音 `qwen-audio-3.1-asr-flash`）基于 MoE Audio-LLM 架构，已在单次语音解码链路中原生解决了流式低延迟与句末整句刷新、P0/P1 分级热词、多轮前文消歧、口语填充/卡顿/改口原生润色以及 30 语种 + 16 种中国方言混说。

若直接将旧链路的本地微调补偿原封不动套在 `Qwen-Audio-3.1-ASR` 上，多项补偿会从“正向兜底”退化为**负向干扰**。

## 2. 既有微调处理正负向逐项评估与改造策略

### 2.1 对 `Qwen-Audio-3.1-ASR` 属于负优化、已在云端识别路径旁路的机制

1. **本地 4s/8s/13s 强制切片与双遍重解码（`DictationSession` + `SherpaQwen3Recognizer.MaxChunkSamples`）**
   - **原因**：该机制专为规避本地 `qwen3-asr-0.6B-int8` 的 512 KV 溢出（`GenerateText:913`）而设；对 `Qwen-Audio-3.1-ASR-Message` 做客户端短切片会破坏其长上下文声学注意力与原生“边说边出字（`sentence_end=false`）+ 句末整句刷新（`sentence_end=true`）”协同机制，并强迫用户额外下载本地 ONNX 模型。
   - **改造**：新增全双工 WebSocket 会话 [QwenWebSocketDictationSession](../../../src/LiveLingo.Core/Speech/Cloud/QwenAudioDictationSession.cs)，直接以 80 ms PCM16 帧流式直推服务端，按 `sentence_id` 原地替换中间结果、在 `sentence_end=true` 落盘刷新结果，并启用 `vad_model="near_meeting_16k"` 与 `heartbeat=true` 保持思考停顿不断连。
2. **36 BPE Token / 24 词热词硬截断（`Glossary.SpeechHotwords`）**
   - **原因**：47-token 告警是 `sherpa-onnx` 本地解码器提示头限制。`Qwen-Audio-3.1-ASR` 原生支持最多 2,000 个即时热词与 P0/P1 两级权重（启用 P0 后近期热词与人名召回率达 99.4%+），沿用 24 词截断会丢弃大量词条并丧失优先级区分。
   - **改造**：本地 `SherpaSpeechEngine` 继续保留 24 词 / 36 token 安全预算；云端新增 [Glossary.CloudSpeechVocabulary](../../../src/LiveLingo.Core/Translation/Glossary.cs)，将用户显式词条与纠错目标词（`UserTerms`）映射为 **P0 超级热词（`weight=50`，上限 50 个）**，内置中英研发术语库（`BuiltInTerms`）与其余词条映射为 **P1 候选池（`weight=4`，总上限 2,000 个）**，并自动过滤超出百炼热词规范（含非 ASCII >15 字符或纯英文 >7 词）的无效项。
3. **孤立切片悬空虚词伪句号挂起（`DictationSession.HoldPrematurePeriod`）**
   - **原因**：本地孤立二遍解码缺少前文，会在中英切换思考停顿时给介词/连词硬补句号；`Qwen-Audio-3.1-ASR-Message` 具备完整句内声学韵律与前文上下文，正则剥句号反而可能误并独立短句。
   - **改造**：`HoldPrematurePeriod` 严格限定在本地 `DictationSession` 内，云端会话直接信任模型刷新后的断句标点，并通过 `run-task` / `continue-task` 持续滚动注入最近 5 轮（每轮 ≤400 字）已识别前文辅助跨句消歧。
4. **默认整理模式下的串行二次 LLM 改写与全文润色等待（`CleanupScheduler` + `PolishScheduler`）**
   - **原因**：正如技术解读所指出，“先 ASR 转写再交由文本模型润色”多出一次串行推理（停麦后额外等待数秒，且需下载/常驻数 GB 本地整理模型），同时纯文本小模型看不见声学重音与停顿，还可能触发 `FidelityGate` 误拒回退。
   - **改造**：当选用支持原生润色的 `Qwen-Audio-3.1-ASR`（`Message` / `Flash`）且开启「整理句子」时，在识别解码中直接开启 `disfluency_removal_enabled=true`：
     - 默认润色要求下，落盘单元标记 `IsNativePolished=true`，`CleanupScheduler` 与 `PolishScheduler` 零延迟直接采用原生润色结果，**无需下载任何本地模型即可零等待口述并回填**；
     - 当用户关闭「整理句子」（需要逐字原话）时自动设为 `disfluency_removal_enabled=false`；
     - 当用户**自定义了全文润色要求**（如特定纪要格式）、**在输入框手动打字/粘贴**，或主动点击**「重新生成全文」**时，仍按需调用整理/润色 LLM 与 `FidelityGate`。

### 2.2 与 `Qwen-Audio-3.1-ASR` 正向互补、予以保留并协同的机制

1. **口音/固定误识别确定性纠错（`Glossary.ApplyCorrections` + 浮窗一键记入）**：右侧正确词注入 P0（`weight=50`）声学热词，落盘时再按整词边界执行确定性替换，且保留 `unit.Raw` 供「改用原话」随时回退。
2. **多模型输出规范化（`TextTidy.Apply`）**：幂等清理偶发特殊标记与全角标点多余空格。
3. **翻译器读取整理稿与前文（`TranslationScheduler` + `Draft.TranslationDocumentInput`）**：`Qwen-Audio-3.1-ASR` 专注识别与同语种润色，其高质量成品文本直接作为翻译器输入，显著减少口吃和错词直译。
4. **本地离线链路完整保留**：默认仍为 100% 本机离线运行；切换至云端语音识别必须经过显式告知“麦克风语音和导入录音将发送至该端点”的隐私授权弹窗，且支持一键「全部切回本机」，开启云端识别时 `ModelWarmup` 不再后台加载本地 ONNX 模型，立省约 1.35 GB 内存。

## 3. 本地免费旗舰 `Qwen/Qwen3-ASR-1.7B` 接入与差异化策略模式（`SpeechOptimizationStrategies`）

考虑到云端 `Qwen-Audio-3.1-ASR` 按 Token 计费，同时引入开源最强免费离线语音模型 **`Qwen/Qwen3-ASR-1.7B`**（目录项 [ModelCatalog.SpeechQuality](../../../src/LiveLingo.Core/Models/ModelCatalog.cs)，ID `qwen3-asr-1.7b-int8`，共 6 个 SHA256 固定的 Hugging Face 资产，支持断点续传与 HF 镜像加速，同时兼容本地 vLLM OpenAI 端点 `Qwen/Qwen3-ASR-1.7B`）。

对 `Qwen3-ASR 1.7B`、`Qwen3-ASR 0.6B`、`X-ASR Offline` 与云端 `Qwen-Audio-3.1-ASR` 进行同标准的正负向微调审计后，发现若共用一套硬编码参数会产生跨模型负优化，因此抽象出统一的策略优化模式 [SpeechOptimizationStrategies](../../../src/LiveLingo.Core/Speech/SpeechOptimizationStrategy.cs)：

| 优化维度 | 云端 `Qwen-Audio-3.1-ASR-Message` | 本地 `#1 Qwen3-ASR 1.7B` (`qwen3-asr-1.7b-int8`) | 本地 `#2 Qwen3-ASR 0.6B` (`qwen3-asr-0.6b-int8`) | 本地 `#3 X-ASR Offline` (`x-asr-offline-int8`) |
| --- | --- | --- | --- | --- |
| **原生口语润色 (`SupportsNativePolish`)** | **是**（默认跳过串行整理/润色 LLM） | **否（逐字转写模型）**：**严禁跳过** `CleanupScheduler` / `PolishScheduler`，否则口头语、口吃与自我改口无法清理 | **否**（保留下游整理/润色 LLM） | **否**（保留下游整理/润色 LLM） |
| **声学切分窗口 (`SoftMax` / `HardMax` / `MaxSegment`)** | **不切片**（`0s`，全双工流式直推，切片属负优化） | **`6.5s / 11s / 15s`**：1.7B 的 28 层语义解码器依赖完整复句消歧同音词与中英混说；4s 早切会造成**语境饥饿负优化**，15s 仅占 ~195 音频 token，安全处于 512 KV 内 | **`4.0s / 8.0s / 13s`**：适配 0.6B 轻量解码与快速周转 | **`8.0s / 15s / 30s`**：非自回归 Transducer 无 512 KV 限制，解除 13s 强切与伪句号剥离负优化 |
| **生成上限与停麦排水 (`MaxNewTokens` / `StopTimeoutMs`)** | 服务端托管 / `10s` | **`224` tokens / `25s`**：修复默认 `128` token 在快语速中英混说下的截断，并给 2.04 GB INT8 模型留足排水时间防止回退流式草稿 | **`192` tokens / `15s`** | Transducer 帧同步 / `10s` |
| **热词策略 (`HotwordMode`)** | **P0(`50`) + P1(`4`)** 分级词表（≤2,000 词）+ 5 轮滚动前文 | **有界系统提示头**（24 词 / 160 字符 / ≤36 BPE token，规避 48-token KV 挤压） | **有界系统提示头**（≤36 BPE token） | **关闭**（`greedy_search` 下传热词属无效开销并阻止常驻复用） |
| **声学对齐与复读防护** | 服务端 RL 抑制 | `sherpa-onnx 2.0.1` 启用 **Centered-STFT 对齐**（消除 5 ms 帧偏移导致的 1.7B 循环崩溃）+ 64-token 退化循环截断 + `15 chars/s` 兜底 | Centered-STFT + `15 chars/s` 兜底 | **关闭 `chars/s` 自回归循环拦截**（消除快语速英文误判） |
| **悬空虚词句号挂起 / `TextTidy`** | **关闭句号挂起**；保留 `TextTidy` | **开启句号挂起**（孤立段无前文）；`TextTidy` 额外剥离 `language <Lang><asr_text>` 前缀 | **开启句号挂起** + `TextTidy` | **开启句号挂起** + `TextTidy` |
| **CPU 线程策略 (`ResolveThreads`)** | N/A | `Clamp(Cores / 2, 4, 8)`（喂满 2.04 GB INT8 内存带宽） | `Clamp(Cores / 2, 4, 6)` | `Clamp(Cores / 4, 2, 4)`（避免小矩阵同步开销） |
| **硬件顾问 (`ModelAdvisor`)** | 0 GB 本机占用 | 32 GB+ 机型及 16 GB 云端卸载时自动设为 `★ 最佳匹配`；16 GB 全本地为可选 `高负载`（选中时自动关闭双 LLM 常驻防抖动）；8 GB 拦截防 OOM | **16 GB M2 基线全本地 `★ 最佳匹配`** | 8 GB 低内存设备 `★ 最佳匹配` |

## 4. 模型选择与接入形态

1. **本地免费语音识别（「设置 → 模型 → 语音识别 → 本机模型」）**：
   - `#1 Qwen3-ASR 1.7B · 旗舰本地识别`（`qwen3-asr-1.7b-int8`，2.40 GB，常驻约 3.0 GB）
   - `#2 Qwen3-ASR 0.6B · 均衡高精度识别`（`qwen3-asr-0.6b-int8`，879 MB，常驻约 1.3 GB）
   - `#3 X-ASR Offline · 轻快识别`（`x-asr-offline-int8`，136 MB，常驻约 0.8 GB）
2. **云端 / 自建服务端点（「设置 → 模型 → 语音识别 → 云端模型」）**：
   - **一键预设 `Qwen-Audio-3.1-ASR`**：`qwen-audio-3.1-asr-flash-message`（百炼全双工 WebSocket，流式上屏 + P0/P1 热词 + `continue-task` 动态前文 + 原生润色）及 `qwen-audio-3.1-asr-flash`（多模态 HTTP）。
   - **自建 vLLM / OpenAI 兼容**：支持填入 `http://localhost:8000/v1` + `Qwen/Qwen3-ASR-1.7B`（自动走 `OpenAiChatAudio` 协议并保留下游整理/润色链路）。
