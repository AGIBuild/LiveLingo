# LiveLingo 2.0 · 用户偏好设计：什么要记住，什么走默认

状态：**已确认，已实施（真机未验证）**。已确认的决定：①“记住每个应用的上次选择”**默认开**；②**不设失效时间**（记忆只受 50 个应用的上限约束，最久未用的先淘汰）；③“唤起后自动听写”**先做全局开关**，按应用覆盖留待后续。相关：[Composer 设计](./2026-10-31-livelingo-composer-design.md) §7.2、[Web UI 设计](./2026-11-01-web-ui-design.md)。

## 1. 要解决的问题

现在每次唤起，浮窗都回到出厂状态：输出总是“整理”，翻译方向总是设置里的默认值。在 Slack 里用户刚选了“翻译成 English”，下次唤起又回到“整理”，要再选一次；而在 Cursor 里和 Agent 讨论时，他要的是“整理”（保持中文）。**同一个人在不同应用里的需求不同，同一应用里的需求又相当稳定。** 反过来，也不能什么都记：把“原话”记住，会让用户悄悄绕过整理；把麦克风记住成“自动开启”，会让用户在没意识到的时候开着录音。

目标：用户在每个场景里**第一次选择之后就不用再选**，并且**不会因为记住了什么而出错或泄露**。

## 2. 原则：一个选择要不要被记住

按顺序问四个问题，全部通过才记住。

| # | 问题 | 不通过的例子 |
|---|---|---|
| 1 | 它描述的是**去向**（谁会读、什么语言）而不是**这份内容**？去向是稳定的，内容是一次性的 | 整段处理、宽屏对照、仅复制：只对这一份草稿成立 |
| 2 | 它是用户的**主动选择**，而不是系统因故障做的切换？ | 处理太慢时点“改用原话”；模型缺失时的回落 |
| 3 | 记错了，**代价小且看得见**？ | 悄悄打开录音、悄悄开启云端：看不见，代价是隐私 |
| 4 | 它**会降低保护**（保真检查、隐私默认）吗？降低保护的选择不跨次保留 | “原话（不整理）”：跳过整理与保真 |

因此得到四种“归属”：

| 归属 | 谁改变它 | 例子 |
|---|---|---|
| **设置（默认）** | 用户在设置里主动改；不会自动变 | 唤起快捷键、回填键、界面语言、主题、减少动画、麦克风设备、翻译档位、术语表、云端开关与密钥、**默认输出**、**默认翻译方向**、**唤起后自动听写** |
| **记忆（每个应用）** | 用户在浮窗里主动选择后自动记录，可忘记 | 该应用的输出（整理 / 翻译）与翻译方向 |
| **推导（由情境得出）** | 不存储，每次由当前情境算出 | 无输入框 → 仅复制；整段文本 → 整段路径与宽屏；导入的转录 → 时间线；浮窗位置与宽度 → 贴着目标窗口、限制在屏幕内 |
| **本次（只在这份草稿内）** | 用户临时切换，唤起后丢弃 | “原话”、整段处理开关、宽屏开关、仅复制开关、浮窗被拖到的位置、听写开关状态、草稿文字 |

## 3. 逐项分类

### 3.1 浮窗里的选择

| 项 | 归属 | 理由 |
|---|---|---|
| 输出：整理 | 默认（设置“默认输出”，出厂为整理） | 是起点，不需要记 |
| 输出：翻译 | **记忆（每应用）** | 去向稳定：给海外同事的 Slack 总是英文；通过原则 1–4 |
| 输出：原话 | **本次** | 跳过整理与保真（原则 4）；用户显式用时再选一次，成本是一个键 `⌘3` |
| 翻译方向（English ↔ 中文） | **记忆（每应用）**，随“翻译”一起记 | 方向属于去向；新应用用设置里的默认方向 |
| 仅复制 | 推导；用户手动切换为**本次** | 有没有输入框是情境，不是偏好 |
| 整段处理、宽屏对照 | 推导；手动切换为**本次** | 属于内容 |
| 听写开 / 关 | **本次**；是否“唤起即听写”见 3.2 | 麦克风是隐私敏感操作，不从行为里学习 |
| 草稿文字 | **本次**；上次未写入的草稿只“提供”不“恢复”（已实现） | |
| 浮窗位置 | **本次**；每次唤起重新贴着输入框 | 拖动是为了躲开遮挡，不是长期偏好；可选“固定位置”见 §8 |
| 系统因故障引起的切换（慢 → 原话、模型缺失） | **不记** | 原则 2 |

### 3.2 设置里的项

| 项 | 归属 | 说明 |
|---|---|---|
| 唤起快捷键、回填键、界面语言、主题、减少动画 | 设置 | 一次性配置，任何自动记忆都会让它“莫名其妙地变” |
| 麦克风设备 | 设置 | 蓝牙耳机会改变系统默认；设备缺失时报横幅，不静默换设备（已实现） |
| 云端翻译 / 整理、端点、模型、密钥 | 设置，**永不记忆** | 扩大数据出境范围必须是显式同意，不能从“上次”继承到新场景 |
| 翻译档位、术语表 | 设置 | 术语按应用分组留作后续（§9） |
| **默认输出**（新增） | 设置 | 整理 / 翻译 / 原话；没有记忆的应用以它为起点。出厂为整理 |
| **唤起后自动开始听写**（新增，出厂关闭） | 设置；可以按应用覆盖（在 §6 的应用列表里） | 想要“一按热键就说话”的用户显式打开；不做“学习式”触发 |
| 导出格式 | **记忆（全局）** | 与应用无关：导出对话框把上次用的格式标出并默认聚焦。文件夹不记——系统文件对话框自己会记 |
| 识别语言、整理强度（后续功能） | 设置为默认；**可按应用覆盖** | 写技术聊天与写文档对“整理强度”要求不同 |

## 4. 场景如何区分

**键 = 目标应用的稳定标识**，不用窗口标题（标题带页面与文档名，属于内容，隐私风险大且不稳定）。

- macOS：bundle id（如 `com.microsoft.VSCode`），而不是显示名；Windows：可执行文件名（小写）。**需要扩展 `IWindowTracker`**：现在 `TargetWindowInfo` 只有 `ProcessName`（显示名），不够稳定。
- 没有输入框（仅复制）：用固定键 `∅`，也有自己的记忆（用户常把它当翻译器用）。
- 三个主要场景自然落在不同应用上：与 Agent 讨论（Cursor、终端、VS Code）、协作沟通（Slack、微信、Teams）、文档（Word、Notion、Obsidian）。**不需要用户建“场景”**：应用就是场景。
- 浏览器、Electron 这类“一个应用里有多个场景”的宿主是已知薄弱点：键仍是应用，但**可见**（§5），错了只需一个键改正，也可以在设置的应用列表里忘记。

## 5. 使用时的规则

唤起时，起点按以下顺序取第一个有效值：

```
本次（只存在于草稿内）  >  该应用的记忆（仍然可用）  >  设置里的默认  >  出厂默认
```

“仍然可用”：记忆里的输出必须是当前提供的输出（例如关闭了整理就没有“整理”）、云端或模型状态允许；**不满足就忽略这一条记忆，不报错**（它不是错误，是已失效的偏好）。

写入记忆的时机：**只在用户主动选择时**——输出药丸菜单、`⌘1` / `⌘2`、互换语言 `⌘L`。系统的切换（“改用原话”等）通过另一条路径，不触发记录。成功写入后刷新这条记忆的“最近使用”时间。

**记忆必须看得见**：当起点来自记忆且不同于默认时，空白状态的提示下面显示一行：

> 已沿用 Slack 上次的选择：翻译成 English · **恢复默认**

输出药丸本来就显示当前状态；“恢复默认”删除这条记忆并回到默认。输出菜单底部再加一行说明“选择会为 Slack 记住”，让这件事不是隐含的。

## 6. 设置里怎么管

- **通用**：开关“记住每个应用的上次选择”（默认开）。说明：只记应用标识与输出、方向；不记标题、文字、录音；仅在本机。
- **语音与翻译**新增：“默认输出”“默认翻译方向”（已有）“唤起后自动开始听写”。
- **隐私与云端**新增：“应用偏好”列表——每行：应用名 · 输出 · 方向 · 上次使用时间 · 忘记；顶部“清除全部”。同一个表将来承载“按应用覆盖”的项（自动听写、整理强度、术语分组），所以**记忆与按应用的配置是同一个概念，不分两套**。用户在这里手工改一行，等价于“为该应用预设”。

## 7. 存储与生命周期

- **单独的文件** `preferences.json`（`SchemaVersion = 1`），不放进 `settings.json`：设置是用户写的配置，会被导出和迁移；记忆是自动产生的、可随时丢弃的。设置导出不含它。
- 内容：`apps`（键 → 显示名、输出、翻译方向、最近使用时间）、`exportFormat`（上次导出的格式）。不含标题、文字、录音、密钥。
- 上限 50 个应用，淘汰最久未用的；**没有失效时间**（已确认）：记忆一直有效，直到用户在设置里忘记它、清除全部，或被更新的应用挤出。
- 原子写入（先写临时文件再替换），防抖；读失败（损坏）时从空开始并记一条不含内容的日志——这是“偏好丢了”，不是错误。
- 只在本机，不同步、不进日志与诊断、不进云端调用。

## 8. 架构

遵守“同一功能一个实现”：

- `ComposerPreferences`（唯一服务，接口 `IComposerPreferences`）：`ComposerStart Resolve(AppKey? app)`、`void Remember(AppKey? app, OutputChoice choice)`、`Forget(AppKey)`、`Clear()`、`Entries`。纯逻辑，时间由 `TimeProvider` 注入，存储由 `IPreferencesStore`（JSON）实现，便于测试。
- `AppKey`：由平台层给出的稳定标识（`IWindowTracker` 增加 `AppKey`，macOS 用 bundle id，Windows 用小写 exe 名）。
- `ComposerViewModel`：构造时接收 `ComposerStart`（起点的输出与方向），不知道记忆存在；新增 `ChooseOutput(output)` / `ChooseTarget(language)` 作为**用户选择入口**，设置值并触发事件 `ChoiceMade`；横幅等系统路径直接设 `Output`，不触发。Web 意图 `output` / `swapLanguage` 走 `Choose*`。
- `App.SummonAsync`：`Resolve(app)` → 构造 VM；订阅 `ChoiceMade` → `Remember`；写入成功时 `Touch`。
- 快照增加 `Source.Remembered`（来源应用名与“恢复默认”）供提示行使用；`restoreDefault` 为新的封闭意图。

## 9. 不做什么（以及为什么）

| 不做 | 理由 |
|---|---|
| 全局“上次用的输出” | 一个应用里的选择会污染另一个应用（在 Slack 翻译后，到 Cursor 变成写英文） |
| 从行为里学习自动听写 | 麦克风是隐私敏感操作，必须显式 |
| 记住“原话” | 它绕过整理与保真；用户要用时 `⌘3` 即可 |
| 按窗口标题 / 网页 / 文档记忆 | 标题是内容，隐私风险大，且不稳定 |
| 同步到其他设备 | 应用标识是个人活动痕迹，默认只在本机 |
| 预置“应用类别”的默认（如终端默认保守整理） | 现在没有这些功能可调；等整理强度等功能存在，且有数据证明有必要再加 |
| 让用户建命名的“场景 / 档案” | 应用已经是场景；多一层概念增加学习成本，用 §6 的应用列表已能覆盖 |

## 10. 开放问题与验证

| 编号 | 问题 | 结论 | 验证 |
|---|---|---|---|
| P1 | “记住每个应用的上次选择”默认开还是关 | **已确认：开**（只记应用标识与两个枚举，本机，可一键清除） | 隐私页明确披露 |
| P2 | 失效时间 | **已确认：不设失效时间** | 用户测试：被记错（沿用了不想要的翻译）的次数；若浏览器类显著偏高，再考虑按域名而不是失效 |
| P3 | 浮窗位置要不要“固定”选项 | 暂不做；若用户反馈每次要拖，再加“固定位置”（菜单里的开关，每块屏幕一份） | 观察拖动频率 |
| P4 | “唤起后自动听写”是否按应用可覆盖 | **已确认：先做全局开关**；按应用覆盖留待应用表扩展时 | 第一期只有全局开关 |
| P5 | 目标应用标识在 Windows 上用 exe 名是否够区分 | 对 UWP / 多个托管同一进程的应用可能不够 | Windows 实机核对；不够再换 AUMID |
| P6 | 提示行与菜单说明会不会干扰 | 只在“来自记忆且不同于默认”时出现 | 用户测试 |
